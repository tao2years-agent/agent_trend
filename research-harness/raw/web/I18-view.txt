L33: 【12†GitHub Agentic Workflows†github.github.com】, an open source project from GitHub Next, is now generally available. With agentic workflows, you can automate reasoning-based tasks like issue triage, CI failure analysis, documentation updates, and test writing by using coding agents inside GitHub Actions.
L34: Define your automation in natural language Markdown files, and GitHub Agentic Workflows compiles them into standard Actions YAML. Because these are GitHub Actions, they reuse your existing runner groups and policy constraints. You can use GitHub Copilot or bring your own coding agent to power each workflow.
L35: > We’ve been rolling out our agentic developer workflows, and the results are measurable. One of our leads saved an estimated 29 hours a week on his development work alone. Across his team, measured velocity has more than doubled on average, and AI now authors 91% of the team’s commits. With these workflows, the team cut production errors from about 11,000 a day to under 1,000 and drove a technology migration end to end.
L36: >
L37: > One workflow takes a feature from requirements to implementation with validation evidence. Others keep our frameworks current and steadily raise code quality and test coverage. Because AI drives the process to completion, our engineers can run four or five efforts in parallel and stay focused on the bigger goals.
L38: > Ben Alton – Senior manager, Strategy, Architecture & Innovation team at Accenture
L39: ### 【9†Built-in safeguards】
L40: GitHub Agentic Workflows incorporates layered safeguards for your automation. Agents access GitHub content respecting the 【13†integrity filter†github.github.io】 rules, run with read-only permissions by default, and execute inside a sandboxed container behind the 【14†Agent Workflow Firewall†github.github.com】. The outputs are validated through the 【15†safe outputs†github.github.com】 process, and a dedicated 【16†threat detection†github.github.com】 job scans all proposed changes before they are applied.
L41: ### 【10†Additional capabilities for general availability】
L42: 
L43: Highlights since the public preview include:
L44:   * Actions Runner Controller (ARC) and Docker-in-Docker support: Run agentic workflows on self-hosted ARC runners with Docker-in-Docker.
L45:   * Improved budget forecasting: `gh aw forecast` is no longer experimental. It now includes both threat detection credits and monthly ranges for a fuller picture of your AI credit spend.
L46:   * New models, engine choices, and workflows: The model inventory has been refreshed, model providers can be picked per workflow, and there are new workflow templates that can be added with `gh aw add-wizard`.
L47:   * Model routing: Workflows can use a model router that optimizes for task type and difficulty.
L48:   * Improved agent isolation: Agents can run in a Cloud Hypervisor or NVX micro-VM and prevent data leaks in cross-repository workflows with enclaves.
L49: See the 【17†GitHub Agentic Workflows release notes†github.com】 for the full list of changes.
L50: ### 【11†Get started】
L51: 
L52: Follow the 【18†quickstart guide†github.github.com】 to install the CLI extension and trigger your first workflow in minutes. Explore prebuilt workflows in GitHub Next’s 【19†agentics repository†github.com】 for ready-to-use examples covering triage, dependency management, code review, and reporting.
L53: GitHub Agentic Workflows is now generally available on github.com for GitHub Free, Team, and Enterprise. Using the default GitHub Copilot CLI engine to power a workflow requires a Copilot license.
L54: 
L55: Learn more in the 【20†GitHub Agentic Workflows documentation†github.github.com】, and join the conversation in the 【21†community discussion†github.com】.
