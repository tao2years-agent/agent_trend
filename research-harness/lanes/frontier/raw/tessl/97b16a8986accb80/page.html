    #Web Changelog

    2026-10-30

    #Weekly update

    Covers changes deployed from October 23 to October 30, 2026.

    #Breaking changes

    • Environments are created in your organization: Workspaces no longer create their own environments. Create environment on a workspace now opens your organization's Environments page, and the API's workspace environment create endpoint returns 410 Gone. Existing workspace environments keep working. See Environments.
    • Linear connects at the organization level: New Linear connections are always held by your organization, including connections made during onboarding and Implement setup. You can no longer connect Linear to a single workspace. Linear isn't available in the EU region. See Least privilege for environments.

    #New features

    • Change your organization slug: Organization admins can change the slug on the organization Settings page. Links and scripts that use the old slug stop working, and the slug is locked while a Customer Managed Gateway is configured. See Administrating organizations.
    • Test MCP server connections: The organization MCP servers page has a Test connection button for each server, and a server whose sign-in the provider rejected now shows Reconnect needed instead of Connected. See MCP gateway.
    • Check your Linear connection: The organization Linear settings page can check the connection and show, for each routed team, whether its issues can start a Loop. See Least privilege for environments.
    • Ignore a Linear team: A Linear team route can now ignore a team, so that team's issues start no runs even when a catch-all route is set.

    #Improvements

    • SSO settings: The Authentication section shows each SSO connection with its status, lets admins delete an email domain, highlights pending domains, and opens setup portals in a new tab. SSO requires a plan that includes it. See SSO.
    • Name your workspace during onboarding: New accounts choose a workspace name during onboarding instead of getting an automatically named starter workspace.
    • Credits by source: The organization Usage page shows each credit source as one stacked bar, in the order credits are spent, and the sidebar shows your balance as "X of Y".
    • Advisory Code Review: In advisory mode the Tessl Reviewer check now ends neutral, and findings it would have blocked on are labeled Should fix. See Set up agentic code review.
    • All-time Code Review statistics: Code Review statistics now cover every review round instead of only the last 30 days.
    • Requested by on runs: A launch run's details show who requested the run, next to who created it.
    • Skill activation for more agents: Eval results now report which skills Codex, Cursor, and Tessl agent runs loaded, not only Claude Code runs. See Reading evaluation results.

    #Bug fixes

    • Fixed Code Review not running on a pull request whose branch lacks the repository's .tessl-code-review.yml.
    • Fixed failed Code Review checks telling you to push a commit to retry. They now tell you to comment @tessl-reviewer.
    • Fixed plugin file pages with long file paths failing to load.
    • Fixed credit usage by actor on the Usage page showing percentages that changed when you filtered by actor type.
    • Fixed opening a table filter scrolling the page to the top.

    2026-10-23

    #Weekly update

    Covers changes deployed from October 16 to October 23, 2026.

    #Breaking changes

    • MCP servers move to your organization: New MCP servers are added at the organization level, and the API's workspace MCP server create endpoint now returns 410 Gone. Servers a workspace already holds keep working. See Register an MCP server in your organization.

    #New features

    • Organization MCP servers: Org admins register and authorize MCP servers from the new MCP servers tab in organization settings, and workspace MCP pages point there. See MCP gateway.
    • Organization secrets: Define a secret once on the new Secrets page in organization settings, and environments refer to it by name. People can rotate or delete a secret but never read its value. See Least privilege for environments.
    • Connect Linear for your organization: Linear now connects from the organization Integrations page, and one connection can route teams to projects in any workspace of the organization. Linear isn't available in the EU region. See Least privilege for environments.
    • Archive a workspace: Workspace settings now offer Archive, and you can restore an archived workspace later. GET /v1/workspaces/{workspaceIdOrName} returns archived. See Workspaces.
    • Claude Haiku 5.5: claude-haiku-5-5 is available as a model for evals and cloud runs. See Evaluate skill quality using scenarios.
    • Organization-wide usage data setting: Organization editors can share CLI usage data for everyone, block it for everyone, or leave the choice to each member. See Sharing usage data.

    #Improvements

    • Clearer Code Review failures: When a managed review fails, the pull request's check now says why. When too many lenses applied, it states the lens limit, and its link opens the review in the Tessl web app. Each repository's Code Review summary also lists its recent reviews. See Set up agentic code review.
    • Readable, live run logs: A run's page has Overview, Logs, and Findings tabs. Logs read as a transcript, follow new events live, and load in full for finished runs. See Troubleshoot factory runs.
    • AI credit pricing: AI usage, including evals, is now billed at model cost, and the platform charge for a cloud run is lower. See Tessl pricing.
    • Projects list shows last activity: The organization Projects list shows each project's latest activity, from runs, Loops, and findings, and sorts by it. See Projects in the app.
    • GitHub connections no longer create projects: Repositories from a GitHub installation appear as choices in the Create project picker, and you create projects only for the ones you want. See Connect Tessl to GitHub.
    • Overall score explained: Skill and plugin pages have a How is this calculated? link that explains the overall score. See Reviewing skills.
    • Eval pages guide next steps: Empty and error states on eval pages offer next steps and retry actions. Activation results now tell a skill that wasn't present apart from one that wasn't used. See Reading evaluation results.

    #Bug fixes

    • Fixed signing in from an identity provider tile, such as Okta, Google, or Entra, landing on the tessl.io homepage instead of the app.
    • Fixed account scans failing when another organization owns some of the account's private repositories, and the Azure DevOps scan scope page failing to load when its organizations had different policies.
    • Fixed archiving a plugin version with a workspace or organization API key failing.
    • Fixed users who hadn't finished onboarding being sent back to onboarding when they opened integrations pages.

Creating a project now suggests a package path when the repository root already has a project. See Projects in the app.
    • Code Review connection status: The Code Review page states clearly whether the Tessl Reviewer GitHub App isn't connected, was uninstalled, is suspended, is missing permissions, or has no repositories. See Set up agentic code review.
    • Context table explanations: Empty Score and Security cells on Context tables now say why they're empty, such as not scored, not reviewed, or not applicable. See Understand your organization's context.
    • Refresh after updates: When a new version of the app is deployed while a page is open, the app asks you to refresh instead of failing silently.

    • Fixed spend from managed GitHub App reviews showing as unattributed on the Usage page. It now shows as organization level.
    • Fixed repository search failing for GitHub App installations on personal accounts.
    • Fixed a GitHub App connection request sometimes recording the wrong GitHub account when you had pending requests for several accounts.
    • Fixed a "Page not found" error right after you completed GitHub onboarding.
    • Fixed the audit log missing the Tessl support badge on some events performed by Tessl support.

    • Project setup status: The project overview page now shows a setup card covering GitHub access, your tessl.json manifest, configured Loops, and schedule health, with a concrete next step when something needs attention.
    • Per-environment Linear access: Workspace environments now have a Linear access setting (none, read, or write), so a launch run's Linear access is scoped to its environment instead of a person's own token.

    • Project search and grouping: The organization Projects list is now searchable by project name, repository, or path, shows a relative last-updated time per project, and groups projects under their repository so a repository's projects no longer split across pages.
    • Clearer project creation: Creating a project now gives specific guidance when no repository is connected, when you lack access, when a search returns nothing, or when loading fails, and lists every repository connection your workspace can see.
    • Context filters in one place: The workspace Context page shows all its filters as a single row of pills instead of hiding most of them behind a "More filters" control.
    • Usage page on every plan: The organization Usage page is now available to admins on every plan, not just Business and Enterprise.
    • Higher automation concurrency: The per-project limit on concurrent automation runs has doubled, from 50 to 100.
    • New accounts get a starter workspace: Signing up now creates a starter workspace automatically, rather than requiring you to create one during onboarding.
    • Eval scenario guidance: The skill and plugin score page now explains how many more eval scenarios are needed for a full score, when fewer than 3 have run.

    #Bug fixes

    • Fixed CLI device-code sign-in saving credentials for an organization your Tessl instance doesn't serve, which made every later CLI command fail; the sign-in page and onboarding guidance also point EU accounts at the correct region and login command.
    • Fixed breadcrumb navigation links occasionally flickering or misbehaving when a breadcrumb segment was added or removed.
    • Fixed long reasoning text in a skill review scorecard overflowing its table cell instead of wrapping.
    • Fixed adding some remote MCP servers, including GitBook, as a connection: Tessl's redirect URI included a query string that those servers' authorization flow rejects.
    • Fixed inconsistent quality scoring on some skills.
    • Fixed an issue where semantic search wasn't finding some private skills.

    2026-10-03

    #New features

    • The publish_plugin, validate_plugin_for_publish, list_plugin_files, and get_plugin_file tools on the remote MCP server now support incremental plugin publishing: agents can apply ordered put, edit, and delete changes to an existing plugin version without re-uploading every file.
    • The archive_plugin and delete_plugin tools are now available on the remote MCP, allowing publishers to archive or permanently delete plugins without leaving their coding environment.
    • Projects have been moved to the Org level.
    • Workspace settings no longer shows a separate Source control section; Linear and other workspace integrations now appear together under a single Integrations section alongside MCP servers.
    • The sidebar navigation is reorganized into three labeled groups: Work, Manage, and Resources. The workspace selector is removed from the sidebar; a Workspaces entry under Manage links to a list page, the Activity page gains a workspace selector, and workspace Settings is accessible from each workspace card.
    • Org admins now have a setting to enable or disable automatic quality reviews dispatched during inventory scans using the automaticQualityReviewsEnabled field. Security scans and indexing continue regardless of this setting.

    #Bug fixes

    • Code Review via the GitHub App now correctly reads pull-request links. The link-selection model is included in every App-managed run key, and documentation pages up to 2 MB are fetched and converted to text rather than being refused for size.
    • The Last changed timestamp on the managed-requirements policy editor now correctly updates when a newer policy is saved.
    • Workspace publishers can now archive, unarchive, deprecate, and undeprecate plugins from the plugin page. Previously only managers could perform these actions.
    • The Automations entry is no longer shown in the workspace sidebar; existing Automations routes remain accessible via direct links.
    • Skill activations now include file reads of installed SKILL.md files via the Read tool, cat, head, and sed, so eval activation counts accurately reflect all skill usage.

    2026-09-28

    #New features

    • Organizations can now run up to 1,000 eval scenarios per day, up from 300.
    • Workspace managers can now mark a plugin as deprecated with an optional reason and replacement. Users viewing a deprecated plugin see a warning banner on its registry page.
    • The findings panel now detects and reports SKILL.md files that exceed 500 lines, explaining what to move to supporting files and providing remediation guidance.
    • Users can now manually trigger a schedule sync for a project from the project Schedules tab. The sync re-reads and validates the tessl.json on the default branch and reconciles schedules, with progress polling and status feedback in the UI.
    • Credit usage is now broken down by platform charges and AI token costs.
    • GPT-6 Luna (gpt-6-luna) and GPT-6 Sol (gpt-6-sol) are now available as model selections for LLM key issuance and agent workflows.
    • Automation trigger conditions now support recursive not, any, and none operator objects and a wildcard path projection for list members, enabling trigger rules that match or exclude events based on nested data.
    • Eval run pages now show a redesigned layout with responsive result and metric cards, scenario comparisons and detail drawers, setup data, persisted run selection via URL, and an Activation section showing per-variant and per-scenario breakdowns of how often agents loaded each skill. The updated view is available in the workspace eval run view, public run links, and plugin eval tabs.

    #Improvements

    • Linear webhook deliveries are now processed exclusively through the factory trigger intake. The legacy Linear task-delegation path is removed: existing workflows built on it no longer function and must be rebuilt using factory triggers via POST /experimental/webhooks/linear. The PATCH /integrations/:integrationId and GET /integrations/:integrationId/linear/metadata endpoints reflect the updated integration shape.
    • The deprecated gpt-5-codex and gpt-5.2-codex model IDs are no longer accepted for eval runs or agent workflows.
    • The default eval model is now DeepSeek V4.1 Flash (deepseek-v4.1-flash), replacing DeepSeek V4 Flash, and the default review model is now GLM 5.3 (glm-5.3), replacing GLM 5.2. Several other deprecated model routes are removed from the catalogue.
    • Workspaces can now create up to 100 active schedules by default, up from the previous limit of 20.
    • When a schedule sync fails, the notifications are sent to the user who edited the schedule last, rather than routing to the workspace administrators
    • Repo-defined scheduled runs now correctly reconcile the declaring manifest before installing and running the target skill.
    • Launch runs can now be filtered by exact label via GET /experimental/launch-runs, enabling more reliable deduplication of run creation attempts.
    • Skill quality and security scores are now correctly preserved across synchronizations when a skill is unchanged, preventing score regressions.
    • Switching workspaces from the sidebar now keeps users on the same screen when the destination workspace supports it, carrying over stable view state.
    • Users can now delete projects from the project overview page.
    • Quality skill reviews no longer generate duplicate review runs when the SKILL.md content differs only in line endings or boundary blank lines, reducing redundant credit consumption.
    • Organizations that spent their Free credit allowance and then upgraded to Team now correctly receive their full Team credit allowance.

    #Bug fixes

    • Disabling a skill review quality score policy (setting it to OFF) now correctly saves and displays as disabled rather than being silently converted to a score of 0.
    • Visitors see a loading spinner and an accessible status message while login navigation is in progress, and the return destination is preserved correctly if the current page changes before login resolves.

    2026-09-21

    #Breaking changes

    • The snapshot field is removed from repo-defined schedule entries in tessl.json. Schedules that declare snapshot are now rejected by schema validation. The field had no effect on schedule execution.

    #New features

    • Azure DevOps integration (Microsoft Entra ID) is now generally available to all entitled organizations. Connect an Azure DevOps organization to discover repositories, scan skills, rescan on demand, and manage scan policy from org integration settings.
    • The login page now shows a region selector that navigates users to the correct regional login and remembers their choice in local storage.
    • A new dryRun: true setting in tessl.json puts trigger automation in observation mode: conditions are traced, action fields are resolved, and each trigger logs whether it would have fired, without claiming deliveries or starting runs.
    • Tessl Code Review credit usage per completed round has changed in both regions. See https://tessl.io/pricing/ for current details.
    • Org and workspace publish policies support an optional minimum skill quality score. When set, publishing a plugin version is blocked until every skill meets the configured threshold.
    • The MCP server detail page shows a live 'Available tools' panel with per-tool descriptions, manual refresh, re-authorization prompts, and distinct error states for unavailability and protocol errors.
    • Context improvement proposals can now target any Markdown file in the repository instead of only AGENTS.md and CLAUDE.md. Proposals go through an editor review step before being published, improving accuracy and placement. Repositories blocked by an unfinished proposal run are automatically released on the next dispatch.
    • Eval run tables now show a skill activation column at the variant, scenario, and repeat levels: which skills were activated, the activation rate, and each activated skill's name in the expanded view.
    • Eval runs using Codex CLI now capture per-turn tool call and token data, enabling turn-level analysis previously only available for Claude runs.
    • Org admins can enable a 'Global install only' toggle in the managed dependencies policy editor to install managed plugins once per machine without per-project declarations.
    • When Code Review fails because the organization has no credits, a comment is automatically posted on the pull request explaining the situation and linking to the pricing page.

    #Improvements

    • 'Enable reviews' on a repository row immediately saves the repository and opens settings pre-configured, without a second toggle inside the drawer.
    • Scheduled runs are more reliable: duplicate fires are rejected, and a schedule targeting a deleted or archived workspace records a durable configuration failure instead of retrying indefinitely.
    • file: skill references in nested tessl.json manifests now resolve relative to the manifest's own directory rather than the repository root, so multi-manifest repositories can use short relative paths without breakage.
    • The integration scan history list on org settings shows 10 scans per page with a 'Load more scans' button, replacing the previous flat list.
    • Quality scores and review results now reflect the selected context version: a version with no completed review returns null scores rather than stale scores from another version.
    • Untracked findings now require complete first-party reference evidence before being reported; incomplete or indeterminate archive evidence is treated as unknown.
    • Skill context occurrences now persist display name and description correctly on both fresh indexing and re-observation of unchanged file versions.

    #Bug fixes

    • Launch run resumes now expire seven days after the workspace was saved; attempts after the window receive HTTP 410. Launch runs retain their original run ID after sandbox recovery.
    • The schedule detail page shows a human-readable description (e.g. 'Every Friday at 9:00 AM') instead of the raw cron expression; the raw string is still accessible on hover.
    • Repo-defined schedules missing project links are automatically repaired after the next manifest sync. Schedules created from trigger-fired runs no longer inherit the original trigger event data.
    • The Schedules breadcrumb on a launch run detail page now links to the owning project's Schedules tab. GET /experimental/launch-runs/{id} includes scheduledRunId.
    • Multi-manifest repositories isolate each project's verifiers and context to the exact tessl.json that defines them.
    • GitHub App accounts can request Code Review approval for pull requests they authored, restoring the address-then-approve workflow.
    • Repository indexing and review dispatch follow source identity through renames and transfers.
    • Authenticated users visiting private registry detail pages are no longer incorrectly redirected before authentication resolves.
    • When creating an environment with conflicting GitHub access settings, the error message uses plain language and explains what to change.
    • Eval runs uploading a local directory no longer fail with a fingerprint mismatch during staging.
    • Launch sandboxes use a pinned, protected image, preventing run failures caused by the image being replaced during execution.
    • Failed-scan alerts on the Home page link directly to the affected SCM provider's integration page and open retryable rows on arrival. Scan history appears inline in integration settings without requiring manager permissions.

    2026-09-14

    #New features

    • Projects are now available at the organization level. Browse projects across your organization, filter them by their backing workspace, and open a project to view its Context, Findings, Evals, and Schedules.
    • New GET /v1/orgs/{orgId}/users and GET /v1/orgs/{orgId}/users/{userIdOrName} list and look up the members of an organization you belong to, with the same response shapes as the user routes they replace. GET /v1/users and GET /v1/users/{userIdOrName} are deprecated in favor of them and remain fully supported.     2026-09-03

    #Breaking changes

    • GET /experimental/tasks renames its link filters from filter[link.type] and filter[link.value] to filter[linkType] and filter[linkValue]. The dotted names are removed with no alias. The old spellings worked only because this route read those two query keys by hand; the shared filter parser matches field names with word characters only, so a dotted key never reaches a route that relies on the parser. The rename aligns these filters with that parser's vocabulary, so filter field names are camelCase throughout.

    2026-09-02

    #Breaking changes

    • GET /experimental/tasks/by-link is removed. GET /experimental/tasks now accepts filter[link.type] and filter[link.value], which return every task carrying the reference, newest first, with the same paging as any other task list. Each filter narrows on its own and the two compose.
    • tessl task by-link is removed. Use tessl task list --link-type and --link-value.

    #Features

    • Several tasks can now link the same external reference. Previously a given pull request URL or Linear issue belonged to exactly one task per workspace, so when a later task reported the same reference it was silently dropped and never showed up in a lookup. A pull request worked on across several review rounds now lists every task that touched it.

    2026-08-26

    #New features

    • Organizations now have their own Home, Context, and Findings pages that roll up every workspace in the org, so you can see context health, quality bands, and security findings across the whole organization in one place. Signed-in users now land on org Home by default, and the sidebar logo navigates there. Inventories owned directly by the org, with no workspace, now appear on these pages too.
    • The organization Insights page shows organization-wide activity: active users, plugin install counts sourced from a nightly snapshot (total, daily series, and top plugins), and per-window timeframe labels on each activity graph. The GET /experimental/orgs/{orgId}/insights response carries an installs object and window.installsThrough.
    • New scheduled runs get a plain-English schedule builder (every N hours, daily, weekly on chosen days, or monthly) with a time-of-day and a Timezone dropdown, keeping raw cron entry behind a toggle for expressions the builder cannot model. The Skill, Repository, and Environment fields become searchable comboboxes, the Agent and Model controls populate from the supported-agents endpoint, and the form links out to environment setup.
    • The scheduled-run detail page shows the schedule author, a linked and summarized Skill, and each run's output as a pull request link or summary. The scheduled-runs table shows a plain-English schedule with its timezone, a Name and Description, and the last run's outcome. Scheduled runs accept an optional description on POST and PATCH /experimental/scheduled-runs.
    • Launch runs can be cancelled through the new POST /experimental/launch-runs/{id}/cancel endpoint. Cancellation is idempotent, tears down the sandbox, and marks the run with a distinct cancelled status. Launch-run reads gain a derived outcome (succeeded, no-action, or failed with a reason) so an agent-reported failure is distinguishable from a completed run, plus a live progress_phase, progress_message, and liveness projection.
    • The native remote MCP server gains a discover, validate, publish, and poll workflow for skill-backed plugins through validate_plugin_for_publish, publish_plugin, and get_plugin_publish_status, an optional pre-publish skill quality review through review_skill and check_review_status, and a read-only list_workspaces tool for workspace discovery. validate_plugin_for_publish now reports every detectable publishing problem in one call. The endpoint serves both the current MCP protocol (2026-07-28) and the legacy version (2025-11-25), and every authenticated tool call produces an audit event.
    • Organizations can run and track a Claude marketplace sync at org scope through POST /v1/orgs/{orgId}/claude-marketplace/sync, GET /v1/orgs/{orgId}/claude-marketplace/sync/latest, and GET /v1/orgs/{orgId}/claude-marketplace/sync/overview. The integration settings page shows a live sync overview with per-plugin status, versions, Quality and Security columns, and run history, plus an Automatic sync toggle (syncEnabled) that pauses scheduled sync while keeping manual sync available.
    • Workspace owners can delete eligible plugins from the plugin detail page through a Delete plugin action and confirmation, without Tessl-admin support. Policy rejections surface the exact reason.
    • New GET /v1/whoami reports what a request is authenticated as, for both user sessions and API keys, discriminated on data.type. GET /v1/users/me is deprecated in favor of it.
    • Feature availability can now be gated by region from a committed policy driven by the TESSL_REGION environment variable: routes marked regionalFeature return 404 where a feature is withheld, and the frontend hides it. The policy ships empty, so nothing is withheld yet.

    #Improvements

    • The BYO LLM gateway is now the Customer Managed Gateway throughout the product. It uses a high, medium, and low model tier selection instead of per-feature model dropdowns: byo-provider responses drop featureDefaultModels and carry tierModels instead, and enabling a gateway now requires a model for every tier. A gateway can be created with a connection and no models while routing is off, so you can save the connection first and add models later. The stored credential shows as a masked, read-only value with a Replace control.
    • Linear can no longer be connected at organization level and is managed at workspace level only. The org-level Linear connect, callback, metadata, and config routes under /v1/orgs/{orgId}/integrations are removed, and Linear no longer appears in org integration listings. Existing workspace-level Linear connections keep working. In a hoisted organization with more than one source-control installation, a workspace's own connection is now preferred over the org's.
    • The launch-run, scheduled-run, and task-run creation endpoints accept a GitHub repository as a bare owner/repo slug, an HTTPS URL, a scheme-less link, or SSH shorthand, normalize it to a canonical https://github.com/owner/repo, and reject unparseable or non-GitHub values with a 400. These endpoints also let internal callers select the standard or Docker-capable sandbox image. Creating a scheduled run from an inline spec now requires an environmentId and rejects the request with a 400 up front instead of failing later at trigger time.
    • A cloud launch that names no GitHub-token source (no uploaded env file and no workspace environment carrying a token) is now rejected with a 400 before the run, workflow, or 100-credit platform fee is created, and the error names both remedies. Checkout is blocked with a 503 unless the whole payment-to-credit pipeline is configured, so a card is never charged against a pipeline that cannot grant credits.
    • Org read endpoints now include the organization slug on GET /v1/orgs/{orgId} and GET /v1/users/{userId}/orgs, and /orgs URLs accept an org id or slug with the slug canonical. GET /experimental/launch-runs and scheduled-run fire history include the configured mcpServers, outcome, summary, pr, and triggerSource fields. Workspace environments can carry MCP servers, which are applied to launch, scheduled, and task runs.
    • Paginated remote MCP list tools now render an explicit page count that states it is not the total and include the exact nextCursor, so agents can page through every result. list_organization_skills and get_skill discover skills contained in published plugins and accept an optional workspaceId filter.
    • Publishing a passing plugin now automatically starts finding enrichment for eligible security findings without blocking, delaying, or failing the publish. Creating an inventory now requires selecting a GitHub organization. The target-repository picker searches across every connected GitHub organization instead of one, and the scan-scope picker shows only repositories already in the policy with a searchable combobox to add more.
