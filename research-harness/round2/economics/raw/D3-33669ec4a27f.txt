AI Credit Limits
This product is not supported for your selected
Datadog site
. (
).
Overview
Organization admins can set monthly caps on AI Credit usage for the organization, for roles, and for individual users. A default per-user limit applies to every user, and admins can override it for individual users. Admins can also set limits for individual service accounts. AI Credits are shared across
Bits Chat
,
Bits Investigation
,
Bits Code
,
Bits Agent Builder
, and
Bits Database Optimization
.
Permissions
To view and set AI Credit limits, a user needs the
billing_edit
permission
.
Where to set limits
AI Credit limits are configured in
Bits AI > AI Credits Management
.
Types of limits
You can configure the following types of monthly limits:
Limit type
Description
Organization-wide limit
Caps total AI Credit usage across the organization for the month. No organization-wide limit is set by default.
Default per-user limit
Caps monthly AI Credit usage for each user who isn’t covered by a role-based limit or an override.
Role-based limit
Caps monthly AI Credit usage for each user with a given
role
.
Per-user override
Sets a custom monthly limit for an individual user, replacing any role-based or default per-user limit for that user.
Service account override
Sets a custom monthly limit for an individual
service account
.
How limits are applied
When more than one limit applies, Datadog checks them in the following order:
Check
Users
Service accounts
Always applied
Organization limit
Organization limit
Priority order
1. Per-user override
2. Highest role-based limit
3. Default per-user limit
1. Service account override
Within the organization limit, Datadog applies the first limit in the priority order that’s set and skips the rest.
Raising a limit unblocks users who reached the previous limit. Lowering a limit blocks users whose usage already exceeds the new value.
When a user or the organization reaches a limit, affected users can’t use Bits Chat, Bits Investigation, Bits Code, Bits Agent Builder, or Bits Database Optimization. A banner shows the reset date.
When a limit is reached, requests to start an investigation through the
Bits AI API
return HTTP
429
with the error code
AI_CREDITS_EXHAUSTED
. A
429
with the error code
INVESTIGATION_RATE_LIMIT_EXCEEDED
means an
investigation rate limit
was reached instead.
Service accounts
Datadog reports
service account
usage separately from user usage. Service accounts have no default limit. Role-based limits and the default per-user limit don’t apply to service accounts, even if a service account has a role with a limit.

Usage attribution
Attribution determines whose limit applies to a given unit of AI usage, and who the AI Credit spend is attributed to. Usage that doesn’t come from a person is attributed to
Autonomous Agents
. Within that total, usage from each service account is also broken out individually.
Product
Attribution
Bits Chat
All Bits Chat usage, including chats inside an investigation, rolls up to the email address of the user interacting with Bits Chat.
Bits Investigation
Manually started investigations roll up to the email address of the user who initiated the action.
Investigations started through the API roll up to the user or service account that owns the API key, and count toward that account’s limits.
Automatically triggered investigations (for example, from a monitor firing) roll up to
Autonomous Agents
.
Bits Code
All Bits Code usage rolls up to the email address of the user interacting with Bits Code.
Bits Agent Builder
Agent runs for workflows roll up to the email address of the user who created the workflow.
Agent runs for workflows created by service accounts roll up to
Autonomous Agents
, and are also broken out by the individual service account.
Get alerted before reaching a limit
To get notified before users reach their limit, use the AI Credits
usage metrics
, grouped by
user_handle
, in a
metric monitor
.
