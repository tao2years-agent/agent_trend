# 预先登记的观察设计

登记于读取数据卡、文件树及 PR/review 的 Parquet schema 后、读取任何行或状态频数之前。作者 v5 固定提交 b8dc67df93e7c11f6f20c84129db7232eb1ec253。脚本将记录本页字节 SHA-256；下列设计与后续适配分开。

**问题**：公开仓库中已被识别为 agent 产出的 PR，等长观察后合并、关闭未合并、仍无终态各占多少？其中有多少在 GitHub 留下可辨识的个人账户同意或要求修改的正式 review？产品仪表盘若只看终态会漏掉什么？

**总体与抽样**：仅 AIDev-pop（作者定义为 >100 stars 仓库）。纳入 UTC 2026-02-01 至 2026-03-01 前创建的 PR，固定每个作者给出的 agent 类别最多 300 项。具体规则按 SHA-256("AIDev-r2-20261120|" + 十进制 PR id) 字典序取最小，不看处置结果、评审数或仓库大小。重复 PR ID 必须去重；同 ID 有不同关键值时停止审计，不随意保留有利行。记录抽样前每个代理的 eligible 数以及全体和样本触及的仓库。总合计是分层抽样结果，同时给出按各层抽样概率校正的总体估计；不当作市场份额。

**主要终点**：每项从 created_at 起追踪 30 天，最长不越过 2026-03-31 UTC 日末。以 merged_at、closed_at 截至该时点构造互斥三类。发生合并优先；已关闭但截至此刻无合并；其余仍无记录终态。关闭未合并是“未合入”代理指标，不能直接判定任务被弃置或由人拒绝。长期开启不算失败。用 7 日窗口及“在每组每仓最多保留散列顺序前 5 项”作敏感性分析。若存在重新打开，快照的最后 closed_at 不能独立还原全部历史；检查 timeline 可支持的复核条件，分别披露。

**人类标签**：只认正式 review 表的 APPROVED 或 CHANGES_REQUESTED，与 PR id 连接，限定 created_at 至观察终点，拒绝使用之后补抓的事件。user_type == User 且账号非机器人后缀/可识别代理账号，称“个人账户标记”，不能验证账号背后的自然人。COMMENTED、DISMISSED、PENDING 单列或排除，PR 合并状态本身不算人工批准。报告两类意见及同时出现，两者可重叠；即使没有记录也不推断无人审阅。

**草稿**：PR schema 无 draft；读 timeline 的事件、时间、PR id，若数据存在 converted_to_draft 或 ready_for_review，计算在窗口中出现过草稿转换的可观测下界，与终态交叉。若未暴露足够字段明确报告“草稿起始/当前状态不可识别”。不得从标题、分支名或 agent 类别猜测为草稿。

**混杂和隐私**：仓库规则、任务难度、工作类型、机器人识别质量、代理采用期、仓库规模及 PR 从未创建的失败都可能改变结果；不作因果排名。只取必要列，不取正文、标题、评语或 diff。项目文件保留来源数据卡、元数据和私隐最小化的匿名样本/派生分层表，不散发原始用户名、仓库名或文本。
