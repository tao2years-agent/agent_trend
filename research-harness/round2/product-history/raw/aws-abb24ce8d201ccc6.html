Change log

The following table describes notable releases and updates for AWS Transform.

Date Title Description Links
2026-11-20 AWS Transform continuous modernization adds AWS Health readiness analysis You can now use AWS Transform continuous modernization to find the code behind your AWS Health planned lifecycle events. The AWS Health readiness analysis finds AWS Lambda runtimes, Amazon EKS Kubernetes versions, and AWS Elastic Beanstalk PHP platforms in your infrastructure code. It flags the ones that are deprecated or reach a lifecycle date within 180 days. Each finding links to an AWS managed transformation that upgrades it. You can start from the AWS Health Dashboard. Documentation
2026-11-18 AWS Transform for migrations adds source actions AWS Transform for migrations now lets you create and run source actions, which run your own scripts on the machines in your on-premises environment during the migration. Describe what you need in the chat, and AWS Transform writes the script and creates the source action for you. You can also provide your own script or an existing SSM Parameter Store parameter. When you work from the AWS Transform MGN delegated admin account, AWS Transform can apply your source actions across all the target accounts of your migration. You can run source actions at any point in the migration, and review their status by source action, source server, wave, or application. Source actions
2026-11-18 AWS Transform for migrations now supports rehosting to AWS Outposts You can now rehost servers to AWS Outposts. Create the connector in the parent AWS Region of the Outpost. Documentation
2026-11-16 AWS Transform for migrations adds a migration dashboard A new Dashboard tab shows your inventory, wave plans, applications, assessments, and migration progress across every job in your workspace, and refreshes as your migration progresses. You can customize the dashboard by describing the change in chat. Migration dashboard
2026-11-16 AWS Transform for migrations keeps your migration data across jobs Jobs in a workspace now share your inventory, wave plans, assessments, and migration progress. New jobs reuse servers and saved wave plans from earlier jobs, and you can ask the agent about inventory history and migration progress. Migration data across jobs
2026-11-16 AWS Transform for migrations adds storage recommendations AWS Transform for migrations now recommends target storage settings for your migrated servers, based on storage assessment data. For Amazon EBS, AWS Transform recommends the volume type, IOPS, and throughput for each source server and adds them to the migration inventory file. For Amazon FSx for NetApp ONTAP, AWS Transform recommends the number of file systems and their storage and throughput capacity, and adds the SVM IDs that you provide to the inventory file. Storage recommendations
2026-11-16 AWS Transform network migration adds support for F5 BIG-IP load balancers AWS Transform network migration can now map F5 BIG-IP load balancers to Application Load Balancers and Network Load Balancers. When you map a source network to new VPCs, provide your F5 BIG-IP configuration. AWS Transform maps each virtual server, shows you how the load balancers differ from your source, and deploys them with your network. A new Migrate source load balancers page describes the steps. Migrate source load balancers
2026-11-16 AWS Transform network migration adds AWS Well-Architected reviews of your network design You can now review your network design against AWS Well-Architected best practices before you deploy it. AWS Transform network migration integrates with AWS Well-Architected Agent. When you map a source network to new VPCs, AWS Well-Architected Agent returns prioritized recommendations for security, resilience, and cost optimization. You choose which recommendations AWS Transform applies to your design, and you apply the others in your AWS account after deployment. Well-Architected review of your network
2026-11-06 AWS Transform for migrations combines assessments and migration planning in one job Migration jobs now include assessments. After you upload your inventory, you can build a business case, plan migration waves, or both, in either order, in the same job. Discovery, assessment, and planning
2026-11-01 AWS Transform for migrations supports multiple target accounts per wave AWS Transform for migrations now lets a single migration wave target multiple AWS accounts. Servers in the same wave can migrate to different target accounts, so you no longer need to split applications into separate waves based on their target account. Documentation
2026-10-30 AWS Transform continuous modernization adds Graviton readiness analysis AWS Transform continuous modernization can now assess the AWS Graviton (Arm64) compatibility of your Java applications. The graviton-readiness analysis checks native libraries, dependencies, architecture-specific code, Dockerfiles, build configuration, and JVM flags. Its findings include a recommended fix that you can apply with a remediation. This feature is available in all AWS Regions where AWS Transform continuous modernization is available. Documentation
2026-10-29 AWS Transform network migration can now use migration plan data as input AWS Transform network migration can now generate your network, or the security groups for your existing VPCs, directly from your migration plan data, so you no longer need to upload a separate network file. AWS Transform uses your server and application inventories and the network connections observed during discovery and migration planning. A new Use migration plan data as network input page describes when the option appears and how it affects network review. Use migration plan data as network input
2026-10-21 AWS Transform assessments add storage for Amazon S3, Amazon EBS, and Amazon FSx for NetApp ONTAP AWS Transform migration assessments now assess on-premises storage for migration to Amazon S3, Amazon EBS, and Amazon FSx for NetApp ONTAP. Upload a storage inventory, such as an RVTools export, and AWS Transform maps each workload to one of these services, sizes it, and estimates its cost, including Single-AZ and Multi-AZ pricing for Amazon FSx for NetApp ONTAP. Documentation
2026-10-19 AWS Transform network migration adds the Design a new AWS network option AWS Transform network migration now supports designing a new AWS network from your requirements, in addition to importing a source network and applying source security rules to existing VPCs. The Design a new AWS network page describes how to select a topology, define your applications and environments, size VPCs, and review the generated network before deployment. Design a new network
2026-10-16 AWS Transform for migrations (including VMware) now available in Asia Pacific (Singapore) AWS Transform migration capabilities are now available in the Asia Pacific (Singapore) Region (ap-southeast-1). You can now create workspaces and run discovery and migration jobs in this Region. Modernization, custom transformation, and mainframe capabilities remain available only in other supported Regions. What's New post
2026-10-15 AWS Transform landing zone capability now supports IaC-only flow The AWS Transform landing zone capability now supports an IaC-only flow. You can run organization analysis and recommendations and generate Infrastructure as Code without direct deployment. IaC-only mode applies when you use a Delegated Administrator connector or a Management Account with an IaC-only preference, and supports AWS CDK, Terraform, and Landing Zone Accelerator output formats. Generate landing zone IaC without deployment
2026-10-15 AWS Transform discovery tool adds SQL Server direct database collection and self-update The discovery tool now connects directly to SQL Server instances to collect database count, Always On availability group membership, cluster role, and read-only replica status. You can also update the discovery tool in place using the new self-update feature, without redeploying the appliance. Additional improvements include VM skip lists for VMware and Hyper-V, and improved handling of non-routable guest addresses. Documentation
2026-09-30 AWS Transform landing zone capability adds support for additional brownfield scenarios AWS Transform landing zone capability now supports additional brownfield scenarios, including existing AWS Control Tower landing zones and landing zones built with AWS Organizations. You can run a foundation gap analysis and expand your landing zone on top of the existing landing zone in your target account. Foundation discovery and planning
2026-09-29 AWS Transform assessments add Amazon MSK Express for Apache Kafka AWS Transform migration assessments now assess self-managed Apache Kafka clusters for migration to Amazon MSK Express. AWS Transform recommends a broker configuration and estimates the total cost of ownership across broker hours, storage, data-in, and cross-Availability Zone transfer, along with a compatibility review of the source cluster. Documentation
2026-09-29 AWS Transform assessments add Savings Plans pricing for Amazon EC2 AWS Transform migration assessments now include Compute Savings Plans and EC2 Instance Savings Plans as pricing options for Amazon EC2 recommendations, alongside On-Demand and Reserved Instances, so you can compare committed-use discounts in your migration business case. Documentation
2026-09-15 AWS Transform landing zone capability adds Delegated Administrator connector and IaC-only support AWS Transform landing zone capability now supports connecting through a Delegated Administrator account, allowing organizations with strict governance policies to use AWS Transform without granting direct access to the management account. When using a Delegated Administrator connector, the capability operates in IaC-only mode, generating Infrastructure as Code artifacts (AWS CDK, Terraform, or Landing Zone Accelerator format) for your own deployment pipeline instead of directly provisioning resources. This provides flexibility for organizations that prefer to manage landing zone changes through existing deployment processes. Connector setup and IaC-only mode
2026-09-08 AWS Transform now available in AWS GovCloud (US-West) AWS Transform migration capabilities are now available in the AWS GovCloud (US-West) Region, so government agencies and regulated organizations can run large-scale migrations in a compliant environment. You can migrate VMware, bare metal, Hyper-V, and database workloads to both the AWS GovCloud (US-East) and AWS GovCloud (US-West) destination Regions. Modernization, custom transformation, and assessment capabilities remain available only in supported commercial Regions. What's New post
2026-08-31 AWS Transform for migrations adds security group modernization AWS Transform for migrations now lets you create, configure, and delete security groups and their rules while reviewing your target network. You can associate a rule with a CIDR range or a source VM. You can also enable security group referencing for a specific rule. Documentation
2026-08-30 AWS Transform for migrations adds Amazon FSx for NetApp ONTAP support AWS Transform for migrations now supports Amazon FSx for NetApp ONTAP as a generally available block storage target, alongside Amazon Elastic Block Store (Amazon EBS). You can migrate block storage directly to FSx for ONTAP within the same migration wave that handles compute and networks. This removes the need for intermediate storage platforms or separate migration tools. This capability is available in all AWS Transform supported target Regions and where Amazon FSx for NetApp ONTAP is supported. Configuring FSx for ONTAP as a target storage type, Supported target Regions, FSx for ONTAP supported Regions
2026-08-28 AWS Transform achieves FedRAMP Class C authorization The AWS Transform service is now in scope for FedRAMP Class C (formerly Moderate baseline) in the US East (N. Virginia) Region. You can use AWS Transform from this region to migrate and modernize resources that are or will be located in any of the US East/US West Regions in order to satisfy FedRAMP Class C compliance requirements. Additionally, AWS Transform MGN is in scope for FedRAMP Class D, and can be used independently to migrate resources that require FedRAMP Class D compliance. What's New post, Compliance in Scope
2026-08-24 AWS Transform for migrations adds security posture migration to existing VPCs AWS Transform for migrations now offers a second network migration option: apply your source security posture to VPCs you have already provisioned. You upload a source network file that contains firewall rules, tag the existing VPCs you want in scope, and AWS Transform matches your source subnets to those VPCs by CIDR and generates the corresponding security groups. You can deploy the security groups directly with AWS Transform or generate Infrastructure as Code (CloudFormation, AWS CDK, Terraform, or Landing Zone Accelerator). Documentation
2026-08-17 AWS Transform for migrations adds application alignment recommendation Guided network recommendations can now identify VPCs that host applications from multiple environments, such as development and production workloads sharing a single VPC. When the environments can be cleanly separated along subnet boundaries, AWS Transform suggests splitting the VPC along that boundary to follow AWS best practices for workload isolation. Subnets and server IP addresses remain unchanged by the split. This recommendation uses application and environment data from your migration plan and is available only after migration planning. Documentation
2026-08-16 AWS Transform for migrations adds stale security group rule removal AWS Transform for migrations now identifies unused inbound firewall rules migrated from your on-premises environment and suggests removing them as part of guided network recommendations. This helps you avoid carrying forward security exposure, such as open inbound access, that no longer serves a purpose. Removal is limited to unused ingress rules, where the absence of observed traffic is a reliable signal that a rule is unused. Documentation
2026-08-15 AWS Transform for VMware rehost enables inventory modifications through chat interface AWS Transform for VMware rehost now allows you to modify server configurations through the chat interface during the inventory validation step. In addition to editing the inventory file directly, you can specify changes for individual columns on specific source servers without downloading and editing the entire inventory file. This provides a more convenient way to make targeted updates to your server configurations. Documentation
2026-08-06 AWS Transform for migrations automates post-launch actions AWS Transform for migrations now automates post-launch actions in the migration workflow. Define actions once at the account level. AWS Transform applies them to each source server across your target accounts through AWS Systems Manager (SSM), using predefined or custom SSM documents. This feature is available in all AWS Regions where AWS Transform is available. What's New post, Documentation
2026-08-03 AWS Transform continuous modernization is now generally available AWS Transform continuous modernization is now generally available. You can analyze and remediate technical debt across source code repositories at scale by connecting GitHub organizations, GitLab groups, and Bitbucket workspaces. Run analyses on demand or on a schedule, prioritize findings, and open pull or merge requests with the fixes. This feature is generally available in all AWS Regions where AWS Transform is available. What's New post, Documentation
2026-08-03 AWS Transform for Windows adds offline SQL Server-to-Aurora conversion AWS Transform for full-stack Windows modernization now supports offline source transformation. You can modernize Microsoft SQL Server databases to Amazon Aurora PostgreSQL without a live database connection. Upload SQL Server Data Definition Language (DDL) files to generate a transformation plan. AWS Transform then converts schemas and code objects, validates functional equivalence, and deploys to Aurora PostgreSQL. This feature is available in the US East (N. Virginia) Region. What's New post, Documentation

2026-07-29 AWS Transform for VMware rehost adds post-launch actions AWS Transform for VMware rehost now enables post-launch actions that automate modernization and validation tasks on each source server immediately after it launches as a test or cutover instance. The agent recommends, configures, and runs actions on your behalf using AWS Systems Manager. Actions can be predefined (available in AWS Transform MGN) or custom (created from existing SSM documents), defined at the account level or customized per server. Documentation

2026-07-03 AWS Transform discovery tool adds Oracle Database support The AWS Transform discovery tool now collects detailed Oracle metadata directly from your databases across VMware, Hyper-V, and bare metal servers. You can discover Oracle instances through direct SQL connections. The tool collects Container Database/Pluggable Database (CDB/PDB) enumeration, component inventory, and datafile sizing. It also captures topology flags for Real Application Clusters (RAC), Data Guard, and multitenant architecture. If you haven't configured database credentials, the tool falls back to OS-level detection. All Oracle versions are supported. Oracle Database discovery

2026-06-17 Model-to-model migration assessment for generative AI workloads AWS Transform now offers a model-to-model migration custom transformation. The transformation assesses your generative AI workloads. It produces a migration plan for moving from third-party providers to Amazon Bedrock. The AI-powered agent scans your codebase to identify every AI SDK and model in use. The agent gathers migration requirements through interactive questions. Then it maps models to Amazon Bedrock equivalents with transparent cost comparisons and production-ready code changes. Supports migrations from OpenAI, Google Gemini, direct Anthropic SDK usage, and open-source models through LiteLLM or Ollama. Handles direct SDK integrations and framework-wrapped patterns including LangChain, LlamaIndex, CrewAI, LangGraph, and multi-provider routing layers. Every requirement traces back to the source code for full auditability. What's New post, Documentation
