    Changelog»

    2026-11-09»

    Features»

    • Run Observability: OpenTofu runs now have an Observability tab. It shows the run outcome, findings with recommendations, the duration of each phase compared with earlier runs, and the items that took the most time. Use it to find out why a run failed or was slow. You can also export the trace, or query the findings and metrics through the GraphQL API. Run Observability is available for native OpenTofu stacks on OpenTofu 1.10.0 and later.
    • Stack dependency actions: You can now manage stack dependencies without Space admin. Two new stack actions are available for custom roles: Manage stack dependencies covers creating, updating and deleting dependencies, and Manage stack dependency references covers adding, updating and deleting output references. Both fall back to Space admin, so existing access doesn't change.

    2026-10-22»

    The trigger object in run policy inputs now includes a stack object at each level of the dependency chain, next to the existing run object. A policy can walk the chain to find out which stack started it, for example to approve a run only when a specific upstream stack triggered it. See trigger chain in policy inputs for details.

    2026-10-20»

    Worker communication via AWS IoT Core (worker-iot.spacelift.io) will now be sunset on March 30, 2027, rather than at the end of 2026. We recommend switching your private workers to the HTTP long-poll transport by January 1, 2027.

    Deprecations»

    • GraphQL AUDIT_WEBHOOKS enum value on BillingTierFeature: Use the AUDITING feature instead.
    • GraphQL space field on ModuleCreateInput: Use updateInput.space instead.
    • GraphQL revisionCreate mutation: Use repoCommitCreate instead.
    • GraphQL runPrioritizeSet mutation: Use runPrioritySet instead.
    • GraphQL STACK_ACCESS enum value on PolicyType: Use ACCESS instead.
    • GraphQL TASK_RUN enum value on PolicyType: Use TASK instead.
    • GraphQL TERRAFORM_PLAN enum value on PolicyType: Use PLAN instead.
    • GraphQL run field on PullRequest: Use runs instead.
    • GraphQL revision query: Use repoCommit instead.
    • GraphQL searchRevisions query: Use searchRepoCommits instead.
    • GraphQL searchRevisionsSuggestions query: Use searchRepoCommitsSuggestions instead.
    • GraphQL revisions field on Repo: Use commits instead.
    • GraphQL revision field on RepoFile: Use commit instead.
    • GraphQL parentRevision field on Revision: Use RepoCommit.parentCommit instead.
    • GraphQL isPrioritized field on Run: Use priorityPreset instead.
    • GraphQL PENDING enum value on RunState: This state is no longer used.

    Removals»

    • Removed GraphQL blueprintDeploymentRollback mutation
    • Removed GraphQL blueprintVersionDeprecate mutation
    • Removed GraphQL blueprintV2Schema query

    2026-10-14»

    Login policies can now tell users why their login was denied. Add a deny_message rule, and its message is shown instead of the generic "login denied by policy" error, both on the login page and when an API key is exchanged for a token. The message is also recorded on the account.login_failed audit trail event, so admins can see why a login failed. See Explaining a denied login for an example.

    2026-10-13»

    Kubernetes worker pools now default to the HTTP long-poll transport, starting with workerpool controller v0.0.46. A new WorkerPool without commsProtocol uses poll with pollCommsURL set to https://app.spacelift.io; US-region accounts must set pollCommsURL: https://app.us.spacelift.io. Existing pools keep the transport already stored on them, and commsProtocol: mqtt remains available until MQTT is retired at the end of 2026.

    2026-10-12»

    Logging in to Spacelift from the CLI no longer logs you out of the browser, and the other way around. Each of these now keeps its own session:

    • the web app
    • spacectl profile login
    • terraform login spacelift.io

    A new login only replaces the previous session of the same kind, so logging in to the web app on a second browser still ends the first one. A spacectl session expires at the same time as the browser session it was created from, but logging out of the browser leaves it running.

    2026-10-09»

    Features»

    • OpenTofu vendor: OpenTofu is now a dedicated stack vendor, separate from Terraform. Select OpenTofu when you create a stack. OpenTofu stacks get settings that only OpenTofu supports:

      • Concise output removes the "Refreshing state..." lines from plan, apply and destroy logs. It is on by default on OpenTofu 1.7 and later.
      • CPU profiling captures a pprof profile per run state. You download it from the run view or the API. It is on by default on OpenTofu 1.11 and later.
      • Structured JSON logs are captured with -json-into on OpenTofu 1.12 and later.

      Each feature needs a minimum OpenTofu version. See the feature support table.

      Terraform stacks that use the OpenTofu workflow tool keep working. You can migrate them one at a time or in bulk. Migration does not touch your state or your resources.

      Upgrade your tooling before you migrate

      Migration changes the stack vendor. Upgrade the Spacelift Terraform provider to v1.53.5 or later and spacectl to v1.26.0 or later first. Older releases fail on their next update to a migrated stack.

    2026-09-23»

    GraphQL changesV3, searchEntityChanges and searchEntityChangesSuggestions now return an explicit error for stacks other than Terraform, OpenTofu and Terragrunt. Use changesV2 for other vendors; changesV3 previously returned an empty list.

    2026-09-17»

    Runs now have a ceiling on how long they can stay unfinished: a run that has not reached a terminal state within 30 days of being created is moved into one. Which state it lands in depends on how far the run got — see automatic termination.

    The new Runs to be terminated widget on the dashboard Overview tab lists the runs due in the next seven days, so you can act on them first.

    2026-09-09»

    Tracked runs created when a pull request is merged are attributed to the commit, the same way as runs created from push events. This fixes downstream stacks in a dependency chain skipping their run when the upstream stack had no output changes.

    As a result, TF_VAR_spacelift_run_trigger now reports vcs/commit for these runs, as it already did for runs created from push events. If your hooks or TF code compare this variable against git, you should also accept vcs/commit: git is only a fallback used when a run has no recorded trigger, such as proposed runs. See the Spacelift environment for the values this variable can take.

    2026-09-04»

    The Usage page now shows private worker usage against your contracted limit, and loads substantially faster than it used to.

    • The Workers tab charts your billed concurrency at your contracted percentile, your contracted limit and the burst budget you have left for the current billing cycle. Previous cycles are available for comparison.
    • Usage running into a contracted limit raises a WORKER_USAGE notification, which you can route to the inbox, Slack or a webhook with a notification policy.
    • Root space administrators are also emailed when the burst budget crosses 80% and again at 100%. This is best-effort and has some conditions attached, described on the page below.

    Contracted limits and these notifications apply to accounts on a negotiated contract. See Private worker usage for how the figures are calculated.

    2026-09-01»

    Spacelift now gives up on runs that have waited a long time for a worker that never arrived. Previously only queued proposed and test runs were cancelled, after two days. A run that had already reached the ready state waited forever.

    • Proposed and test runs are cancelled after two days in the queued or ready state. Only the ready part is new.
    • Tracked runs, tasks and destroy runs are cancelled after seven days in the ready state. These hold the stack lock, so anything queued behind them was stuck too.
    • Runs you have already confirmed, and runs waiting for a replan, are failed seven days after they last changed. Both pick up a workspace saved earlier in the run, and that workspace is only kept for seven days, so past that point a worker has nothing left to resume.

    Runs older than thirty days are settled without a notification, so clearing the backlog does not notify you about work from years ago. Newer runs notify as any cancellation does.

    The most common reason a run waits forever is a private worker pool with no workers, either because the launchers were removed or because they were never started.

    • Private workers: Workers now upload run observability artifacts to a new object storage bucket. If your egress rules allowlist individual bucket endpoints, add the new run observability bucket next to the run logs bucket, or worker uploads will fail. If your workers allow Amazon S3 in the installation region, as worker pool network security recommends, nothing changes.

    2026-08-27»

    Deprecations»

    • GraphQL acceptedTermsAndConditionsAI query: Use spaceliftIntelligenceTermsAccepted instead.
    • GraphQL bedrockInferenceProfiles query: Use availableAIModels with the Bedrock provider, providerIntegrationId and providerConfig.bedrock.region instead.
    • GraphQL latestTermsAndConditionsVersionAI query: Use spaceliftIntelligenceTermsLatestVersion instead.

    2026-08-21»

    Deprecations»

    • GraphQL sharedModules query: Use sharedModulesV2 field instead.

    Removals»

    • Removed GraphQL changeLLMVendor mutation
    • Removed GraphQL llmVendor query

    2026-08-18»

    From now on, the terraform_version and terraform_workflow_tool fields in policy input are only returned for the Terraform vendor. For all other vendors, including the dedicated OpenTofu vendor, they are null. Previously, these fields could contain data for non-Terraform vendors. Stacks that use the Terraform vendor with the OpenTofu workflow tool are not affected and keep both values.

    2026-08-04»

    Features»

    • Module local-preview permissions: You can now grant module local-preview access through the MODULE_UPLOAD_LOCAL_WORKSPACE and MODULE_PROPOSE_LOCAL_WORKSPACE actions without granting broad SPACE_WRITE access. Existing users with Space Writer access continue to be authorized through the legacy fallback.

    2026-07-21»

    Security»

    • OIDC API key subject expression now requires a full match: An OIDC API key's subject expression must now match the entire sub claim of the JWT, not just part of it, so a key scoped to repo:my-org/my-repo no longer accepts repo:my-org/my-repo-exploit. If an existing key starts failing with OIDC token subject "…" does not match the expression, anchor its expression to the whole subject — for example, ^repo:my-org/* becomes ^repo:my-org/.*.

    2026-07-20»

    Features»

    • HTTP long-poll worker transport: Private workers can now receive work over HTTP long-poll instead of MQTT. A poll-mode worker only needs outbound HTTPS (port 443) to your Spacelift server, with no connectivity to an MQTT broker or the AWS IoT Core endpoints required, simplifying firewall and egress rules. Enable it by setting SPACELIFT_WORKER_COMMS_PROTOCOL=poll and SPACELIFT_WORKER_COMMS_URL=https://app.spacelift.io (https://app.us.spacelift.io for US-region accounts), or through the commsProtocol/pollCommsURL fields on the WorkerPool resource for Kubernetes workers. Worker communication via AWS IoT Core (worker-iot.spacelift.io) is being sunset at the end of 2026; HTTP long-poll is the recommended transport going forward.

    2026-07-16»

    From now on we will be reporting GraphQL depreciations and removals to give our customers better visibility in API changes. Below you can find a list of currently deprecated entities.

    Deprecations»

    • GraphQL UPDATE_BLUEPRINT_DEPLOYMENT enum value on Action: Use UPGRADE_BLUEPRINT_DEPLOYMENT instead.
    • GraphQL UPDATE_BLUEPRINT_DEPLOYMENT_INPUTS enum value on Action: Use UPGRADE_BLUEPRINT_DEPLOYMENT instead.
    • GraphQL admin field on ApiKeyInput: Please use accessRules or roleBindings with root admin permission instead.
    • GraphQL spaceID field on ApiKeyRoleBinding: Use space field instead.
    • GraphQL secret field on AuditTrailWebhook: This property is no longer used.
    • GraphQL sensitive field on BlueprintDeploymentCreateInputPair: Input type is used to determine whether the input is secret or not, so this field is no longer needed.
    • GraphQL runID field on BlueprintStackCreation: Use the runIds field instead.
    • GraphQL stackID field on BlueprintStackCreation: Use the stackIds field instead.
    • GraphQL email field on ManagedUserInviteInput: Please use invitationEmail instead.
    • GraphQL sharedAccounts field on Module: Use moduleShares field instead.
    • GraphQL blueprintDeploymentCreate mutation: Use templateDeploymentCreate instead
