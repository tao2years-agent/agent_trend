# 预先固定的矩阵和验收条件

实验日期 2026-11-20。按协作角色选提供方 `react` 与同版本 `react-dom`，消费者为 React Testing Library（RTL）；按代际取 `17.0.2、18.2.0、19.0.0` 与 `12.1.5、13.4.0、16.1.0`，九格全跑。结果揭示前已将辅助依赖冻结为 `jsdom@24.1.3`、直接依赖 `@testing-library/dom@10.4.0`。绝不对旧 RTL 内部的 DOM 依赖加 override；npm 可按发行包声明并存不同的 DOM 版本，并从实际安装图记录解析结果。现代 Node 24.14.0、npm 11.9.0，Windows，统一开发模式，未复现各年历史宿主。

每格新建 npm 项目，直接版本精确到补丁、执行 npm install --strict-peer-deps；公共 npm 只读取，关闭 audit、fund 和安装生命周期脚本。若严格安装明确返回 ERESOLVE，则全数另开项目执行 --legacy-peer-deps，并标明不受支持。网络、权限、测试脚手架问题不能算作版本错配。按阶段记录 require、初次呈现、可访问性查询、输入、提交、点击、改变 props 后保留组件状态、卸载与副作用回收。不启动监听服务，测试组件无外部 API。另做一格额外阴性对照：React 19.0.0 / RTL 16.1.0 / DOM 9.3.4，其他条件同，检验 RTL 16 的 DOM peer 本身会不会提前拒绝。对照不计入九格。

交付内容包括发布包 SHA-512 integrity 与本地 SHA-256、包内真实运行时代码位置、严格与宽松两层结果、成功安装的 lockfile、环境与复跑脚本。所有发行包及脚本的结论限于登记输入；没有企业仓库、生产浏览器、npm 全生态分布或真实模型参与评测。后续如加桥接版本或更改测试必须单列。
