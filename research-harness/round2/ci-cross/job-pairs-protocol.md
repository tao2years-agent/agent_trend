# 跨粒度追加方案

已知 GHARuns footer、表结构和行组区间；尚未读取连接键或查看任何 workflow 与 job 的配对结果。为避免仅用两个边际分布猜测一次运行的情况，在 run 表 check_suite_id 全局最小至最大跨度的 10%、50%、90% 位置各取连续 1,000,000 个整数键（闭区间）。扫描两个表中元数据 min/max 与三段有交集的所有行组，只取连接键及前一步的状态列。先检查 suite 的 run 行是否唯一；多义 suite 排除并计数。只发布汇总，不保留真实键。三个区间不是时间随机样本，不能据此给全平台估比；可以验证一个整场 run 失败时部分 job 是否成功、最终 run 成功是否也可能包含失败 job。所有落在区间内的 job 行都参加，单列没有任何 job 的 run，对“成功 run 含失败 job”不推断允许失败、重跑、数据采集、并发或其他具体成因。
