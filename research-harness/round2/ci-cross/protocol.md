# GitHub Actions 跨生态复核方案

在计算新样本任何总数前固定。已阅读三篇论文正文，查看 Huang/Lin 两份表的列名、各首行的数据形状以及 GHARuns 的 Parquet footer；已观察到首行“job rerun”可从 success 开始，此点单列披露。使用作者发布的完整项目数据，不接触真实仓库凭据、原始构建日志、提交消息或漏洞条目。

**不同单位。** Huang/Lin 固定提交 080aa9edd5f54c4e9dc5675ea75bc0f545c37ff3。其 job rerun 表跟随同一 workflow run id 的 previous_attempt_url，可重建各次 workflow conclusion；不能因此宣称知道特定 job 会转绿。其 workflow rerun 表由相邻的不同 run id、相同 SHA 或无项目文件变更的判据组成，属于作者识别的重跑集合，不能冒充 GitHub 原生 attempt。读必要列，按 run id 或有序 run id 元组去重，报告重复和缺失、开头是否失败，以及首次重跑、任一次和最终结局。分析首要分母是长度≥2、初始明确 failure 且第二次明确 success/failure 的不重复原生 run；其他结果仍保留分母。分别给按项目等权与按 run 微平均，区分 red→green 与 green→red。第三套数据为真正的单个 job 结果单位，不混算。

**全运行与未重跑。** GHARuns 2026-10-19 固定 Zenodo 23458821 含 238 天、130,338,516 个 workflow run 元数据行和 221,534,997 个 job 行；其 runs 只保留最后一次 attempt。目标全量取 runs 的 attempt/status/conclusion；jobs 的 status/conclusion；只读取这些 Parquet 列，验证每个 Range 和 SHA256。若服务的节流反复阻断，预设替代以固定 seed SHA256 排序选前 24 个 row group（两个表分别排序，估计时声明非逐行随机）；不把样本当全量。报告“采集时 attempt=1 且 failure”的绝对数、重跑末次结果及真实 job 结局边际；仅有末次结果不能断定重跑开头是否红，也不能给未重跑反事实。主样本和这套数据跨时间/仓库，不能相除。

**留出采购试验。** Huang 表没有墙钟时间。对稳定唯一原生 run id 排序，前60%训练、后续20%选择阈值、末20%测试；明确这是按 ID 的有序留出，不将其等同日期留出。仅用同仓之前样本的红后第二次转绿率，向训练总体加20个虚拟观测收缩；开发固定规则在保留≥95%转绿的阈值中选压低派发数者，分数并列一起处理、可全派。另复算90%、99%和全派，并以最末测试分母冻结，列实际派发、避免继续红、误挡已转绿、阈值、回收率、每少派一次成本/误挡损失的平衡比。对留出 run 的结果不作为特征。不使用日志或外部模型。并报告同 ID 的多次 attempt 中第二次仍红、后面才转绿的情况，“一次不翻绿”不等于永远失败。若可校验表中 attempt 记录缺失，另限制匹配作者长度字段做敏感性。任何数值都不能跨生态照搬采购。

来源和读取故障保留。输出仅汇总数及复现代码，来源快照保留一手论文、公开研究表或其不可变指针，不再分发真实 run/job id、日志正文和仓名级结论。既有 OpenStack 最末 70,740 个已主动要求重跑的请求为独立参照，不与 GitHub 样本拼接。
