# 研究复核协议与覆盖边界

本轮截至 2026-11-20（上海）。面向维护 code agent 的产品与研发平台团队，核心问题是：在执行器之外，哪项组织工作值得接手、由谁监督、怎样独立证明价值。本版使用本会话可用的联网研究、并行研究和本地执行工具。ChatGPT 官方 Deep research 有专门的启动界面；本项目没有以那个界面启动或安装同名产品。[官方功能说明](https://help.openai.com/en/articles/10500283-deep-research-in-chatgpt)

### 用什么定义竞品与前沿

本项目的资料筛选、逐项阅读、独立复核与代码执行均由 Codex 研究代理完成。“独立复核”指不同研究任务或可分别运行的计算路径。涉及真人的用户研究均另行标出论文作者、招募对象和测量方式。本项目没有另聘人类研究者给文献打标签。

直接竞品按同一个“用户能委派并验收的工作”划组。只计实际可购买、可启用或可自行运行的工作产品。将 35 项分入 10 类，每个产品只算一个主任务，另外标记其跨组的替代关系。35 个产品比的是一组相关市场，不能视为一个市场内的 35 家同质对手。首轮的 50 个产品、开源项目及底层组件仍保留为技术地图，其中 36 项看过固定修订的实现，这两种数目与评估工具专题不可相加。明确了进入样本的证据和排除理由，但样本由问题驱动，没有全世界可售产品的抽样框。[采购与筛选](buyers/result.md)

所谓 SOTA，在这里指公开材料能够支持的特定能力、特定评测协议或真实工程实践。研究把历史 benchmark、厂商生产规模、研究原型和可用产品分别标记。模型、任务、预算、验收或可用地区不同，无法用一个总分选出通用赢家。

### 每项判断如何进入 Wiki

1. 记录研究问题、候选来源与快照，给产品、论文、发布单元、实验输入保留可回查的标识。按“官方文档描述”“固定源码显示”“局部运行观察”“公开现场报告”“本研究推断/建议”记录证据性质。主张只继承它实际依赖的那种证据。
2. 给相似产品相同输入、失败条件和验收终点，标明哪些是文档预期、哪些真的运行。逐仓权限、回执丢失、旧批准再投和人不回应都是有能力区分实现的例子。公开信息里没有相应说明，记录未知。
3. 给主要结论至少一个能推翻它的对照：强手工或规则基线、留出仓库/时间、反复失败和放弃、看得见的与看不见的人工决策。跑完修正有影响的主张，保留原版、反证和方法变更。
4. 从同一结果表生成比较和阅读视图。正文里的本地数据下载来自本次构建时的原文件；产品卡引用官方来源，逐项开放网页需联网。完整计算另依赖记录的固定公开资料、本地依赖和下载缓存。HTML 本身可离线阅读。

### 学术检索怎样迭代

依据 CCF 的软件工程、系统软件、程序设计语言目录，选择与主题最贴近的 ICSE、FSE、ASE、ISSTA，各看 2025、2026 官方主研究轨的接受目录。四个会议在 CCF A 类目录中，未把 ESEM、ICLR、预印本或企业工程博客充入这些会议的数目。八届有 1,738 个 event UUID，题名普查不是全文阅读。首轮 142 个命中逐条取官方作者摘要，89 个直接相关。第一次随机抽查的未命中中发现直接相关样本，促成第二轮检索。第二轮排除已知项，再对新增命中和剩余未命中从各届分别抽取，固定哈希、留出未见摘要。词表与两轮筛查都保留，读者可提出新规则继续证伪。[CCF 目录](https://www.ccf.org.cn/Academic_Evaluation/TCSE_SS_PDL/) · [官方分轨覆盖](venue-frame/result.md) · [全部初筛命中](venue-review/result.md) · [下一轮召回审计](recall/result.md)

早期专题挑选的 20 篇中，18 篇读到正文的具体方法或结果，P07 和 P15 在本次环境仍为摘要级证据。另有独立补读与作者原始处理表复算。论文总数有重叠，用 DOI、题名及作者归并；不同来源框的深读数不直接相加。研究组按可追踪的共同署名或项目延续建立，未按声望或引用数投票。[论文复核](papers/result.md) · [研究团队](recall/groups.md)

### 重要结论的重放路径

|要检查的判断|先查哪处|如何复算或者推翻|
|---|---|---|
|两种工具评审率差异随对照变化|[PR 样本](empirical/result.md)、[所有配对](cohorts/result.md)|先用最小样本 verify.py 复算，再按 AIDev 锁定 revision 提取各列，改变共同仓月阈值；要证明效率仍需要工时和独立验收。|
|同类例外能否批修或路由|[迁移](migration/result.md)、[路由](pairing/result.md)|用相同发行快照跑确定性规则，移去某仓重算；执行器分配切分独立冻结，保留所有切分。|
|审批恢复和业务写入是否安全|[双引擎实验](handoff/result.md)|先看 2 个原生寻址对照，再重试写后掉线、关卡重投、版本变化，直接读目标侧独立 SQLite 行数。|
|通过测试究竟是什么保证|[真实问题和金标](oracles/result.md)|从指定 base 应用上游 test patch，对原件和金标跑同一集合，再跑整模块和不完整补丁，保留所有 skip、xfail 和 error。|
|论文中看似矛盾的团队数字|[论文统计量](papers/result.md)、[研究版本](throughput/result.md)、[作者数据复算](replication/result.md)|从原表区分分母、采用意向和采用者；替换比较组、分组单位与检验，重新计算。|
|产品是否已在特定时间提供某能力|[发布单元](evolution/result.md)|核对发布正文和日期，再读相邻标签的实现 diff，区分新功能、无效参数、预发布与只改文档。|

### 能从研究得出什么，不能得出什么

现场报告能说明一家公司按某种方式运行过，公开 PR 说明看到了什么动作，局部运行能建立有限环境里的反例。三者都不能直接回答你们的采用率、净节约或哪条线上的风险可接受。所有试点阈值、场景规模、预计谁批准属于研究建议；真实内部流程、合同价格、真实服务恢复、权限集成与同预算的所有商业产品对跑仍待验证。

### 如何在另一轮研究复用

从项目根目录进入 `round2`。阅读器及基础核验的 Python 包版本见[构建环境](state/environment.json)。CI、真实工具和论文统计的复算各有单独依赖与固定数据，不需要为只读分享页安装它们。

|工作|入口与产物|
|---|---|
|Ingest|先确定比较任务、截止日和证据类型，保存新版本及获取时间。沿各专题的来源表下载已公开数据。会议全目录入口为 `python abstract-index/ingest.py`，保留 UUID、官方来源与各次快照。遇到失败记入专题清单，不把失败页充作正文。|
|Query|从 [Wiki 问题索引](index.md) 或采购产品卡开始。对会议语料运行 `python abstract-index/query.py --build`，再试 `python abstract-index/query.py "handoff OR interruption" --limit 10`，可加 `--venue fse-2026`。索引返回已归档题目、UUID 和官网。从匹配项进入研究卡，只有记录了判读和页码/定位的条目才取得对应证据等级。|
|复核与修订|有新证据时先比对旧字段、时间与适用版本，修到 facts/ledger、源注释或生成器，保留纠错记录。较大结论至少加一条能推翻它的对照。可单独运行 `python cowork/check.py` 对账作者包，或 `python empirical/verify.py` 重算公开抽样。高成本实验按各专题协议跑。|
|Lint 和发布|先 `python catalog.py --strict`、`python publish.py`、`python check_reader.py`，再运行 `python verify.py`。检查页面标题与锚点、桌面/手机溢出、真实附件下载、纸张分页、来源引用以及关键数值。工作目录外的完整报告与两种分享稿落在 `../outputs`。|
