# 上游整模块对照预注册

在查看 Linux/Windows 整模块运行结果之前锁定。8 个已选问题不变。独立于节点实验的第二个解释器使用 Windows 官方 CPython 3.11、全新 venv，固定 pytest 7.4.4、mpmath 1.3.0、numpy 1.26.4、scipy 1.13.1。补充可用的 numexpr 2.10.2，以增加 lambdify 合作库覆盖；对其他未装可选库保留真实 skip、预期失败或导入/收集失败。不得伪装旧官方 Docker 环境。下载依赖仅用于准备；测试本身无需远程服务。如启动同一类固定测试存在外部服务依赖，记录相应问题，停止该模块而不删节点来求全绿。

对每个 case，从 base_commit 的干净上游归档出发，分别以（A）原生产代码和其原测试、（B）原生产代码和完整公共 test_patch、（C）金标生产代码和同一套完整 test_patch 运行 test_patch 引用的每个上游测试模块。已声明的多 hunk 部分候选加做（D）同一组整模块。每个 pytest 子进程只接收一个模块路径，墙钟上限 480 秒；全局最多两个 pytest 子进程。另保留 3.12 首轮小样本的结果，不据新版结论替换旧报告。记录环境库、测试收集数量、pass/fail/skip/xfail/error、退出码、耗时、缺失、超时、测试名字与原始报告。无环境失败不虚构，环境失败保留。

主要比较（1）B 和 C 使用相同测试，完整测试集合中除 FAIL_TO_PASS 外是否存在修复前红、后绿或前绿、后红的真实节点；（2）部分候选相对 C 是否出现预选 FTP/PTP 节点没能抓到的新回归，尤其是短 oracle 接受而全模块拒绝的候选；（3）两种方案实际判别数与观测时间。将原生 SymPy 测试包装器的跳过/预期失败和真正的回归区分，并保留 pytest 的原始状态。成本以子进程秒加和和运行墙钟分别报告，两个 Python 环境的耗时比较只作说明。
