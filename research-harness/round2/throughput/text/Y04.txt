Does Working with AI Agents Change How
Developers Code, Test, and Review?

      Abstract
AI coding agents such as GitHub Copilot and Claude Code are increasingly contributing pull
requests (PRs) autonomously across large-scale software repositories. While prior research has
primarily investigated the quality and acceptance of agent-generated artifacts, less is known about
how sustained exposure to AI agents influences developers’ own practices. Drawing on automation
complacency theory, we investigate whether agent adoption is associated with changes in coding
effort, testing discipline, and code review behavior. We conduct a longitudinal study of 669 developers
across 103 repositories using the AIDev dataset and analyze behavioral changes before and after
agent adoption across 11 metrics. To distinguish agent-associated effects from broader ecosystem
trends, we complement within-subject analyses with a difference-in-differences (DiD) design using 228
control developers from repositories without agent activity. We find one large agent-associated effect:
a 76.8% increase in PR description length (r = 0.561), alongside consistent but smaller improvements
in testing discipline across all three testing measures. Coding effort remains stable. Although review
behavior changes noticeably – reviews become faster, less detailed, and more permissive – these
patterns are also observed in control repositories and therefore appear to reflect broader ecosystem
trends rather than agent adoption. Overall, we find no evidence that developers reduce productive
effort when working with AI agents. Instead, developers increase documentation and testing activity,
while apparent declines in review thoroughness are better explained by wider changes in software
development practice. These findings not only clarify how developers adapt to AI coding agents
but also demonstrate how comparative causal designs help distinguish agent-associated behavioral
changes from broader ecosystem trends.

 1      Introduction
AI coding agents such as GitHub Copilot, Cursor, and Claude Code are increasingly becoming
part of everyday software development workflows. Beyond generating code suggestions,
these agents now act as semi-autonomous collaborators that submit pull requests (PRs),
generate tests, and respond to developer feedback [11, 10]. Large-scale datasets such
as AIDev report hundreds of thousands of agent-authored contributions across diverse
repositories [11], suggesting that AI agents are no longer experimental tools but an emerging

       part of contemporary software engineering practice. As AI agents become increasingly
       integrated into development practice, an important question emerges: how does sustained
       collaboration with AI agents reshape developer behavior? Understanding this shift is
       important because software quality depends not only on generated artifacts, but also on how
       developers review, test, document, and maintain oversight during development.
           Prior research has primarily focused on the outputs of AI agents rather than their influence
       on developers themselves. Existing studies have examined PR acceptance patterns [16, 22],
       code quality [9, 20], and testing practices in agent-generated contributions [25, 8]. Yet
       it remains unclear how sustained collaboration with AI agents influences developers’ own
       practices over time. This question is methodologically challenging because developers who
       adopt AI agents may already differ from non-adopters, while behavioral changes over time
       may also reflect broader shifts in software development practices rather than the effects of
       AI agents themselves.
           To understand this, we draw on automation complacency theory [14], which predicts
       reduced human monitoring and verification effort under reliable automation. In software
       engineering, this suggests that developers working alongside AI agents may change how they
       code, test, and review software over time. Accordingly, we investigate the following research
       question.
           RQ: How does the observable adoption of AI coding agents reshape developers’ coding
       effort, testing practices, and code review behavior?
           To answer this question, we conduct a longitudinal study of 669 developers across
       103 repositories using the AIDev dataset and complement within-subject analyses with a
       (DiD) design using 228 control developers from repositories without agent activity. Our
       findings reveal selective behavioral adaptation rather than broad behavioral degradation.
       Agent adoption is associated with increased documentation effort and improved testing
       discipline, while changes in review behavior largely reflect broader ecosystem-wide trends
       rather than agent-associated effects. These findings make two contributions. Empirically, they
       show that developers maintain coding effort while strengthening documentation and testing
       practices when working with AI agents. Methodologically, they demonstrate that relying
       on within-subject analyses alone can misattribute broader ecosystem trends to AI-agent
       effects, highlighting the importance of comparative causal designs when studying AI-assisted
       software development.


        2     Related Work
       Prior research on AI-assisted software development has largely focused on short-term pro-
       ductivity gains and developer interactions with coding assistants. Controlled experiments
       show substantial improvements in task completion speed – for example, Peng et al. [15]
       report a 55.8% increase in task completion speed with GitHub Copilot, while Ziegler et
       al.[26] find similar perceived productivity benefits. However, complementary usability studies
       reveal a more nuanced picture: developers may accept AI-generated suggestions without
       thorough verification [21], exhibit varied interaction patterns [3], and face inefficiencies when
       evaluating generated code [13]. This literature is largely limited to short-term interactions
       and self-reported perceptions, leaving longer-term behavioral adaptation comparatively
       underexplored.
           Beyond productivity, prior work has examined core development practices such as code
       review and testing, both of which are central to software quality. Code review research
       shows that practices converge across projects [17], serve broader functions such as knowledge
       transfer [2], and are strongly associated with software quality [12]. Additional work highlights
       the importance of factors such as comment specificity and reviewer familiarity [5].

    Recent studies extend this line of inquiry to AI-generated contributions, showing differ-
ences in how developers review agent-authored PR [7]. Existing work, however, primarily
examines the evaluation of agent-generated artifacts rather than broader changes in de-
velopers’ review practices following sustained agent exposure. Similarly, testing practices
have been studied through the lens of test–production co-evolution. Prior work shows that
co-change between production and test files is a meaningful indicator of testing discipline and
relates to downstream quality outcomes [19]. More recent studies investigate test generation
by AI agents [25, 8], demonstrating variation across tools.
    As with code review, this literature primarily focuses on agent-generated artifacts rather
than longer-term developer adaptation. It remains unclear whether developers change their
own testing behavior when working alongside agents. We therefore examine whether test
inclusion and co-change patterns shift following agent adoption, and whether such changes
are agent-associated or reflect broader ecosystem trends.



 3     Research Method

We investigate the effects of AI agent adoption on developer behavior using a longitudinal
within-subject quasi-experimental design, complemented with a DiD analysis [6] to better
distinguish agent-related changes from broader ecosystem trends. For each treatment
repository, we define the adoption point as the timestamp of the first observable agent-
authored pull request, representing the earliest repository-level evidence of autonomous
AI-agent participation. Behavioral changes are analyzed at the developer level, allowing
each developer to serve as their own baseline while controlling for stable differences such
as coding style, experience, and project context. To distinguish agent-related changes from
broader temporal trends, we compare 103 treatment repositories with 148 control repositories
that contain no agent activity. Because control repositories do not have a natural adoption
event, we use the median pull request creation date as a pseudo-adoption point to partition
repository history into balanced pre- and post-periods. This provides a consistent temporal
reference for estimating developer-level behavioral changes while avoiding arbitrary calendar
cutoffs and ensuring comparable pre/post partitions across repositories. We further assess the
suitability of this construction by examining pre-adoption parallel trends between treatment
and control groups (Figure 1).



Dataset and Sampling. Our analysis is based on the AIDev dataset [11]. We retain
repositories that exhibit sustained agent activity spanning at least 90 calendar days, defined
as a minimum of 90 days between the first and last agent-authored pull request, contain
human-authored merged PRs in both pre- and post-adoption periods, and include at least
one qualifying developer, yielding 103 treatment repositories. We retain developers who
contributed at least five merged PRs in both periods within the same repository, a threshold
chosen to balance statistical stability with sample retention. For the control group, we identify
148 repositories with no agent activity and apply the same developer criteria, yielding 228
qualified developers. To ensure data reliability, we remove invalid timestamps, exclude
review turnaround times exceeding 720 hours (30 days), and retain only reviewers active in
both periods. Coding-related metrics are filtered to reduce the influence of extreme values,
and when developer-period groups exceed 20 PRs, we randomly subsample 20 to balance
statistical stability and computational cost.

       Metric Operationalization. We operationalize developer behavior using 11 metrics across
       three dimensions, aggregating all measures per developer per period using medians for
       volume-based metrics and means for proportions. Coding effort is captured through PR
       size, files changed, commits per PR, and PR description length. Testing discipline is
       measured via test file ratio, co-change rate, and production-conditioned co-change rate; test
       files are identified using standard filename heuristics (e.g., test_, _test, .spec, /tests/),
       which likely undercount modern co-located or implicit testing practices and therefore yield
       conservative estimates. Finally, review behavior is assessed through inline comments, review
       turnaround time, changes-requested ratio, and approval rate.

       Statistical Analysis. We analyze behavioral changes using both non-parametric and para-
       metric methods. Within-subject differences are tested using the Wilcoxon signed-rank
       test [23], which is robust to non-normal paired distributions and extreme values, with rank-
       biserial correlation (r) reported as the effect size. To distinguish agent-related changes from
       broader ecosystem trends, we evaluate per-developer DiD deltas using the Mann-Whitney U
       test. As an additional robustness check, we fit two-way fixed-effects models [24] of the form
       yidt = αi + λt + β(Postrt × Treatr ) + ϵidt with repository-clustered standard errors, allowing
       us to account for stable unobserved differences across repositories and time periods. Because
       several outcomes are right-skewed, these models are used to validate the consistency of the
       findings rather than as the primary basis for interpretation. To further reduce selection
       bias between treatment and control repositories, we perform one-to-one nearest-neighbor
       propensity-score matching [18] based on programming language and log star count (caliper 0.2
       standard deviations), achieving 83.2% language overlap and a median log star-distance of 0.52.
       We also conduct a dose-response analysis by dividing repositories according to the median
       level of agent activity (14 PRs) to examine whether stronger agent exposure is associated
       with larger behavioral changes. All p-values are adjusted using the Benjamini–Hochberg [4]
       procedure across 11 tests (α = 0.05). Compared with within-subject analyses alone, the DiD
       design provides stronger evidence for agent-associated behavioral changes. However, the
       seven-month observation window captures only short-term behavioral changes; longer-term
       dynamics, including the gradual emergence of complacency effects predicted by classical
       theory, remain an important direction for future work.

4.1    Coding Effort
We next examine how developers’ coding effort changes after agent adoption. Figure 2 depicts
the distributional shifts across all four coding effort metrics. Overall, coding effort remains
largely stable, with one notable exception: a substantial increase in PR documentation.
Detailed within-subject statistical results are available in the replication package [1].

PR Size. shows no significant change (padj = 0.805, r = 0.011, negligible). The near-equal
split between developers who increase versus decrease PR size (49.8% vs. 50.2%) indicates
the absence of any systematic directional shift. Despite agents generating substantial code in
the same repositories, developers do not reduce the volume of code they personally write
following the first observable agent-authored pull request. Similarly, Files Changed and
Commits per PR shows statistically significant within-subject differences (padj = 0.004
and 0.022, small effects) despite identical medians. These effects reflect compression in the
upper tails of the distribution: developers who previously submitted broader, multi-file PRs
narrow their scope, while the majority remain stable. However, this same pattern is observed
among control developers in the DiD analysis (Table 2), indicating that it reflects broader
ecosystem trends rather than agent-associated effects.
    Additionally, PR Description Length shows the largest effect among all coding effort
metrics. The median increases from 304.0 to 537.5 characters (+76.8%, padj < 0.001,
r = 0.561, large), with 65.3% of developers increasing their descriptions and a median paired
difference of +117 characters. This represents a broad-based behavioral shift rather than
an outlier-driven effect. Notably, this pattern runs counter to automation complacency:
communication effort increases, rather than decreases, following agent adoption.

tion length remains significant when compared against the control group. Treatment de-
velopers increase descriptions by +121.5 characters, while control developers show no change

     Changes in review behavior are not uniquely associated with agent adoption. Although

4.4     Synthesis of Findings
The results across all 11 metrics reveal a clear pattern: agent-associated changes are concen-
trated in productive development activities, whereas most review-related changes align with
broader ecosystem trends. Table 5 summarizes the findings across all analyses. Only four
metrics are consistently supported across analytical methods (bold rows in Table 5): PR de-
scription length and all three testing discipline measures. Across these dimensions, developers
produce more detailed documentation and show stronger coupling between production and
test changes following agent adoption. In contrast, the remaining seven metrics are not sup-
ported as agent-associated effects. PR size remains stable under both within-subject and DiD
analyses, while files changed and commits per PR show within-subject differences that disap-
pear under DiD validation, suggesting broader ecosystem trends rather than agent-associated
effects. Most notably, all four review metrics remain highly significant in within-subject
analyses but lose significance under DiD validation. Although overall directional patterns
are clear, developers differ substantially in both the magnitude and direction of behavioral
change. For example, 65.3% of developers increase PR description length after adoption,
whereas 34.7% decrease it; similarly, 34.8% increase inline review comments while 65.2%
decrease them. This heterogeneity suggests that responses to agent adoption are shaped by
contextual factors such as repository norms, development practices, and developer roles. The
exposure analysis strengthens the interpretation of the documentation effect. Developers
in high-exposure repositories increase PR description length by +107.4%, compared with
+67.5% in low-exposure repositories, indicating that the magnitude of the effect scales with
agent usage. This gradient is consistent with behavioral adaptation rather than incidental
template reuse. Overall, the findings support a pattern of selective behavioral adaptation.
Agent adoption is associated with measurable changes in development behaviors, particularly
documentation and testing practices, while evaluative review behaviors evolve alongside
broader ecosystem dynamics independent of agent presence. Automation complacency, as
classically defined, is therefore not supported by the observed comparative evidence.


 5      Discussion
Across coding, testing, and review activities, our findings reveal a clear asymmetry: agent
adoption is associated with changes in productive development behaviors, whereas most
apparent changes in review behavior are better explained by broader ecosystem trends than
by agent adoption itself.

        Revisiting the complacency hypothesis. Automation complacency theory predicts reduced
        monitoring and verification effort when humans interact with reliable automated systems [14].
        Our findings both challenge and refine this expectation in the context of AI-assisted software
        development. Developers do not appear to disengage from productive engineering activities
        following agent adoption. Instead, the observed improvements in documentation and testing
        practices suggest active behavioral adaptation, where developers invest additional effort in
        communication and verification when collaborating with AI agents. At the same time, the
        review-related changes initially resemble classical complacency patterns: reviews become
        faster, less detailed, and more permissive. However, these patterns are also present in
        repositories without agent adoption, suggesting that they reflect broader shifts in software
        development practice rather than direct effects of AI agents themselves. Our findings therefore
        do not support a classical automation complacency interpretation of code review behavior.
        Instead, they point toward a wider ecosystem shift in review practices, potentially driven by
        increasing development velocity, growing reliance on automated quality assurance tools, and
        evolving collaboration norms in modern software engineering.


        Explaining the observed effects. Several mechanisms may explain the increases in doc-
        umentation and testing effort. One possibility is social adaptation: developers repeatedly
        exposed to structured agent-authored contributions may gradually adopt similar practices
        themselves. Another possibility is compensatory behavior, where developers invest more effort
        in explanation and verification to reduce uncertainty around AI-assisted code changes. The
        stronger effects observed in high-exposure repositories are consistent with this interpretation.
        An alternative explanation concerns the timing of the intervention itself. Our adoption point
        corresponds to the first observable agent-authored pull request rather than the first use
        of AI-assisted programming tools within a repository. Developers may already have been
        using AI coding assistants such as GitHub Copilot, ChatGPT, or Cursor before autonomous
        agent-authored pull requests became visible. Consequently, our findings should be inter-
        preted as behavioral changes associated with the transition to agent-based development
        workflows rather than the initial adoption of AI-assisted software development. Earlier
        exposure to AI coding assistants may also attenuate observable changes in coding-related
        metrics, such as pull request size, if behavioral adaptation had already begun before the
        observation window. Another possible explanation is that repositories adopting autonomous
        coding agents may simultaneously introduce new contribution templates, documentation
        practices, or workflow conventions that encourage more detailed pull request descriptions

and stronger testing practices. Although the observed exposure gradient is more consistent
with behavioral adaptation than simple template reuse, these explanations cannot be fully
disentangled using observational repository data. We also note that PR description length is
an operationalization of communication effort rather than communication quality. Longer
descriptions do not necessarily imply clearer or more useful documentation, and future work
should complement quantitative measures with qualitative assessment of PR content. More
broadly, the consistency of the testing improvements across multiple operationalizations
suggests that the observed pattern is unlikely to be explained by measurement artifacts
alone. In contrast, the review-related changes appear to reflect broader ecosystem evolution
rather than agent-associated adaptation. Similarly, inline review comments, approval rates,
and review turnaround time capture observable review behavior rather than review quality
itself. These measures may also be influenced by factors such as pull request quality, team
conventions, or increased use of automated quality assurance tools. Increasing development
velocity, widespread adoption of CI/CD pipelines and automated quality tools, and shifting
expectations around lightweight review processes may all contribute to faster and less detailed
reviews across software projects generally. From this perspective, AI agents may coexist with
these trends without necessarily driving them directly.

Methodological implications. Our findings highlight the importance of comparative re-
search designs when studying AI-assisted software development. Several effects that appeared
significant under within-subject analyses disappeared after comparison with control re-
positories, demonstrating that broader ecosystem changes can easily be misinterpreted as
agent-associated behavioral effects when comparative controls are absent. Longitudinal
within-subject analyses remain valuable for controlling developer-level heterogeneity, but our
results suggest that they may be insufficient on their own for distinguishing agent-associated
changes from concurrent ecosystem trends. Furthermore, because control repositories lack a
natural intervention point, the pseudo-adoption date is based on the median pull request
creation date. Although this enables balanced longitudinal comparisons, future work should
investigate alternative constructions of comparable control windows (e.g., symmetric pseudo-
observation windows or calendar-matched controls) and incorporate richer repository-level
matching variables, such as project activity, contributor structure, CI practices, or review
culture.

Practical implications. We find no evidence that agent adoption reduces productive en-
gineering effort. Instead, developers maintain coding effort while improving testing and
documentation practices. In contrast, declining review thoroughness appears to be an
ecosystem-wide challenge rather than a challenge uniquely associated with agent adoption,
suggesting that improving review quality will require broader process interventions rather
than restricting agent use. At the same time, the observed increase in documentation
practices may represent a valuable opportunity for improving knowledge transfer, onboarding,
and maintainability in collaborative development environments.


 6     Conclusion and Future Work
This study examined whether AI coding agent adoption changes how developers code,
test, and review using a longitudinal within-subject design with comparative validation
across 669 developer–repository pairs. Our findings reveal a pattern of selective behavioral
adaptation. Agent adoption is associated with stronger documentation and testing practices,

        while coding effort remains stable. In contrast, changes in review behavior reflect broader
        ecosystem-wide trends rather than agent-associated effects. More broadly, our findings
        challenge straightforward applications of automation complacency theory to AI-assisted
        software development. Developers do not appear to disengage from productive engineering
        activities when working with agents. Instead, the strongest agent-associated effects involve
        increased communication and verification effort. Methodologically, the study also highlights
        the importance of comparative research designs for distinguishing agent-associated behavioral
        changes from concurrent ecosystem evolution.
            Several directions can extend this work. Future studies should strengthen causal identifica-
        tion under heterogeneous treatment timing, investigate the qualitative mechanisms underlying
        documentation and testing changes, and examine whether these behavioral patterns persist
        across longer time horizons, different agent types, and enterprise development settings.
