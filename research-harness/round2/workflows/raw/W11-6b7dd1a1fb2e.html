November 9th updates

Highlights

Ask for merges in Agentic Batch Changes

Ask Agentic Batch Changes to merge your changesets, then confirm each merge in the conversation.

Agentic Batch Changes can now merge your changesets when you ask it to.

Nothing merges until you click Allow on the card the agent shows in the conversation. The card lists the changesets with problems first, such as merge conflicts or failed checks. The merges then run in the background. When they finish, the agent picks the conversation back up on its own and reports which changesets merged and which failed, so you don't have to keep checking.

Filter, preview, and compare commits on the commits page

Find the commit you're looking for and see what it changed without leaving the commit history.

The commits page now helps you narrow down a repository's history and look at changes right next to the list. Filter by message, author, and date, step through diffs with the keyboard, and compare any two commits in place.

Filter commits

Search commit messages, filter by author, and limit the list to a date range with Since and Until. The author filter matches part of a name or email and suggests recent contributors as you type. Filters are part of the URL, so you can bookmark or share a filtered view. Commits are grouped by day, and in the history of a file or directory, each folder in the path links to its own history.

Preview diffs next to the list

Click a commit to open its diff in a panel beside the list. Press j and k (or the arrow keys) to move to the next or previous commit, and Esc to close the panel. In the history of a file or directory, the diff starts out limited to that path, with a toggle to show all files.

Compare two commits

Select two commits with the checkbox that appears when you hover over a commit, and their comparison opens in the same panel. The list highlights the commits that the comparison includes, and Open comparison takes you to the full compare page.

Expand context and show full files in diffs

Reveal the code around a change, or the whole file, without leaving the diff.

A diff only shows a few lines around each change, which often isn't enough to understand it. You can now reveal the hidden lines right in the diff on commit, compare, and changeset pages, or show the whole file with the changes highlighted inline.

Use the arrows next to a hunk header to reveal 20 more lines above or below a change, or click the header itself to show all the lines it hides.

Click Full file in a file's header to see the entire file. While it's open, the header counts the changes in the file, and its arrows jump to the previous or next one. You can also press n and p. Click the button again to go back to only the changes.

The full file view replaces the separate full file mode. To open the file as it was before or after the change, use View file before change or View file after change in the file's menu.

Better visibility into files skipped during indexing

Spot repositories with skipped files and see exactly why each file was left out.

When Sourcegraph indexes a repository, it skips some files, for example because they are too large or binary. You can't search the contents of those files, so it's good to know which ones they are. Until now, you had to open each repository's settings to find out.

The new Skipped files page under Administration → Repositories lists every repository with skipped files. Search for a repository or sort by count, then click one to open its Settings → Search Indexing page.

There, each indexed branch now breaks its skipped files down by reason: too large, binary, too many trigrams, and too small. Each count links to a search that lists those files, so you can see exactly what's missing from the index.

Hand over an Agentic Batch Changes thread

Ensure Agentic Batch Changes are not blocked by one person.

You can now hand over an Agentic Batch Change to another user. The new owner can continue the conversation, and publish changesets. Before, a thread stayed with the person who started it, and would therefore stall when they went on leave or left the company.

Open Share on the thread, switch to the Hand over tab, and pick the new owner. From then on, the agent acts as the new owner: it reads with their repository permissions and publishes with their credentials. You keep read access to the thread, and the share link stays the same.

Administrators can hand over any thread, including threads of users who were deleted. This needs the Batch Change Agent Administration: Manage permission on the Roles page, which the Administrator role has by default. If the new owner cannot read some of the repositories in the thread, the picker warns you before you confirm, and those workspaces are hidden from them and from the agent.

A handover waits until the agent is idle. Read more in the documentation.
