在本地与云端之间接续任务（Handoff）

复制页面

使用任务接续（Handoff）功能，可以在本地与云端之间切换任务的运行环境，并继续原有对话：

  • 在云端执行任务：适合需要长时间运行任务，或离开电脑后继续处理任务的场景。
  • 在本地执行任务：适合需要使用本地开发环境继续处理任务的场景。

接续任务时，系统会检查本地与云端的代码状态。如果本地有未提交的修改，或者两端同名分支各有未同步的提交，你需要选择如何处理代码差异。

适用范围

仅 Agent 窗口中的任务支持在本地与云端之间接续。

前置条件

接续任务前，需确保：

  • 目标任务的当前会话已结束。任务中仍有会话在运行时，无法将该任务迁移到另一开发环境。你需要等待当前会话完成或手动停止当前会话。
  • 项目已关联目标 GitHub 仓库。暂不支持 GitLab、Gitee 等其他代码托管平台。
  • TRAE 已获得 GitHub 授权，并且当前账号拥有相应的仓库权限。关于如何连接 TRAE 与 GitHub，参考连接 TRAE 与 GitHub。

将本地任务转至云端执行

将本地任务转至云端执行时，系统会同步任务对话记录，并根据本地与云端的代码状态，将本地代码同步至云端或提示你选择代码处理方式。接续完成后，任务将在云端环境中继续执行。

  1. 在左侧任务栏中，将鼠标悬浮至目标本地任务（确保任务中已无运行中的会话）。
  2. 点击任务右侧的 更多操作 图标，然后选择 转至云端执行。
  3. 系统检查本地与云端的代码状态：
    • 如果代码可以直接同步，系统会自动开始接续任务。
    • 如果存在需要处理的代码差异，需选择一种代码处理方式，详情参考选择代码处理方式。
  4. 等待代码和任务对话记录同步完成。接续完成后，你可以在云端任务中继续与 AI 对话。

将云端任务转至本地执行

将云端任务转至本地执行时，系统会同步任务对话记录，并将云端代码同步至与任务关联的本地项目；如果两端存在代码差异，系统会提示你选择代码处理方式。接续完成后，任务将在本地环境中继续执行。

  1. 在左侧任务栏中，将鼠标悬浮至目标云端任务（确保任务中已无运行中的会话）。
  2. 点击任务右侧的 更多操作 图标，然后选择 转至本地执行。

    界面上弹出窗口，用于选择继续任务的本地文件夹。
  3. 如果是首次将该任务转至本地执行，选择用于继续任务的本地文件夹。

    提示

    所选本地文件夹必须与云端任务关联同一个 GitHub 仓库。完成绑定后，再次将该任务转至本地执行时会继续使用此文件夹，无需重新选择。

    系统开始检查本地与云端的代码状态。
    • 如果代码可以直接同步，系统会自动开始接续任务。
    • 如果存在需要处理的代码差异，需选择一种代码处理方式，详情参考选择代码处理方式。
  4. 等待代码和任务对话记录同步完成。接续完成后，你可以在本地任务中继续与 AI 对话。

选择代码处理方式

出现以下任一情况时，系统会要求你选择代码处理方式：

  • 本地有未提交的修改。
  • 本地与 GitHub 仓库上的同名分支各有未同步到另一端的提交。

发生此类情况时，系统会弹窗进行提示。接续任务前，你需要在该窗口中选择如何处理未提交的修改。

可选处理方式如下：

处理方式 将本地任务转至云端执行 将云端任务转至本地执行

交给 AI 处理

AI 分析两端代码差异，并处理可能的冲突。确认处理结果并同意继续后，系统会重新检查代码状态，并自动将任务转至云端执行。

该方式会消耗积分，具体消耗以界面提示为准。

系统先将任务及其对话记录同步至本地，再由 AI 分析代码差异并处理可能的冲突。确认处理结果后，即可在本地继续执行任务。

该方式会消耗积分，具体消耗以界面提示为准。
使用本地代码 如果本地有未提交的修改，系统会先自动提交；随后将本地代码和任务对话记录发送至云端，并使用本地版本继续任务。仅存在于云端的代码改动不会保留到接续后的任务中。 仅将任务对话记录同步至本地，并使用当前本地代码继续任务。本地分支、代码和未提交的修改均保持不变；系统不会额外提交修改、创建备份或切换分支。
使用云端代码 仅将任务对话记录发送至云端，并使用当前云端代码继续任务。本地分支、代码和未提交的修改均保持不变。 系统先创建备份分支，保存当前本地状态；如果本地有未提交的修改，系统会自动提交到备份分支。备份完成后，系统再将云端代码和任务对话记录同步至本地，并使用云端版本继续任务。

选择处理方式前，请先确认需要保留哪一端的代码：

  • 如果两端的改动都需要保留，建议选择 交给 AI 处理，并仔细检查 AI 的处理结果。
  • 如果只需要保留本地或云端一侧的代码，可以选择对应的处理方式，并留意表格中的代码保留规则。

取消或重新发起任务接续

  • 接续开始前取消：不会更改代码或任务的运行位置。
  • 接续开始后中断：部分步骤可能已经完成，系统不会自动回退所有改动。
  • 重新发起接续：系统会根据最新的代码、权限和任务状态重新检查，不会沿用上一次的检查结果。
  • 网络中断或请求超时：接续结果可能暂时无法确认。恢复连接后，请先检查任务的运行位置和代码状态，再决定是否重新发起。

常见问题

无法切换任务的执行环境

检查当前会话是否已结束。任务仍在运行时，无法迁移到另一开发环境。等待任务完成或手动停止任务，再重新尝试切换任务的执行环境。

提示没有 GitHub 仓库权限

确保 TRAE 已获得 GitHub 授权，并检查当前 GitHub 账号是否拥有相应权限：将本地任务转至云端执行时需要推送权限，将云端任务转至本地执行时需要拉取权限。恢复权限后，重新发起接续。

转至本地执行时找不到可用项目

所选项目必须与云端任务关联同一个 GitHub 仓库，并且项目目录可读写。

已绑定的本地项目被移动或删除

需将项目恢复到原路径，然后尝试重新将任务转至本地执行。任务绑定本地项目后，暂不支持在转至本地执行的过程中更换绑定目录。

接续过程中 Git 操作失败

根据界面显示的具体原因，检查本地修改、分支状态、仓库权限或 Git 配置。解决问题后，重新发起接续。

如果系统已成功创建备份分支，但后续代码更新失败，原本地代码仍保存在该备份分支中。
