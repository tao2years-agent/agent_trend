L4: # DevOps Agent IAM permissions
L5: 
L6: AWS DevOps Agent uses service-specific AWS Identity and Access Management (IAM) actions to control access to its features and capabilities. These actions determine what users can do within the AWS DevOps Agent console and Operator Web App. This is separate from the AWS service API permissions that the agent itself uses to investigate your resources.
L7: 
L8: For more information about limiting agent access, see 【16†Limiting Agent Access in an AWS Account】.
L9: To let the agent perform directed actions in your AWS accounts, register an elevated IAM role on the account association. For example, you might use an elevated role to remediate an issue after operator approval. For more information about directed actions and registering an elevated IAM role, see 【17†Working with directed actions】.
L10: ## Agent Space management actions
L11: 
L12: These actions control access to Agent Space configuration and management:
L13: 
L14:   * aidevops:GetAgentSpace – Allows users to view details about an Agent Space, including its configuration, status, and associated accounts. Users need this permission to access an Agent Space in the AWS Management Console.
L15: 
L16:   * aidevops:GetAssociation – Allows users to view details about a specific account association, including the IAM role configuration and connection status.
L17:   * aidevops:ListAssociations – Allows users to list all AWS account associations configured for an Agent Space, including both primary and secondary accounts.
L18: 
L19:   * aidevops:AssociateService – Allows users to add a service association, such as an AWS account or a third-party tool, to an Agent Space.
L20: 
L21:   * aidevops:UpdateAssociation – Allows users to change the configuration of an existing association, such as its IAM role or credentials.
L22:   * aidevops:DisassociateService – Allows users to remove an association from an Agent Space.
L23: 
L24:   * aidevops:ValidateAwsAssociations – Allows users to check that the AWS account associations of an Agent Space are configured correctly.
L25: 
L26:   * aidevops:ListWebhooks – Allows users to list the webhooks that belong to an association.
L27: 
L28: Resource-level permissions for association actions
L29: Association actions authorize against the Agent Space, and some also authorize against the association itself. Use the request to determine which resources an action checks:
L30:   * An action that targets one association, identified by an association ID in the request (for example, GetAssociation), authorizes against two resources: the association ARN, `arn:aws:aidevops:region:account-id:agentspace/agent-space-id/association/association-id`, and the Agent Space ARN. A statement that allows such an action must cover both ARNs.
L31:   * An action that targets the associations of an Agent Space as a group, without an association ID in the request (for example, ListAssociations), authorizes against the Agent Space ARN, `arn:aws:aidevops:region:account-id:agentspace/agent-space-id`.
L32: Granting an action on `arn:aws:aidevops:region:account-id:agentspace/*` covers both cases, because the pattern matches the Agent Space ARN and the association ARNs under it. A statement scoped only to an association ARN does not grant access to an action that targets one association, because it does not cover the Agent Space ARN.
L33: 
L34: Tag conditions apply to the Agent Space, because associations do not carry tags.
L35: 
L36: To restrict association actions by Agent Space tag, use two statements:
L37:   * One statement without a condition, scoped to the association ARN.
L38:   * One statement with the tag condition, scoped to the Agent Space ARN.
L39: 
L40:     `{
L41:       "Version": "2012-10-17",
L42:       "Statement": [
L43:         {
L44:           "Effect": "Allow",
L45:           "Action": [
L46:             "aidevops:GetAssociation",
L47:             "aidevops:UpdateAssociation",
L48:             "aidevops:DisassociateService",
L49:             "aidevops:ListWebhooks"
L50:           ],
L51:           "Resource": "arn:aws:aidevops:us-east-1:111122223333:agentspace/*/association/*"
L52:         },
L53:         {
L54:           "Effect": "Allow",
L55:           "Action": [
L56:             "aidevops:GetAssociation",
L57:             "aidevops:UpdateAssociation",
L58:             "aidevops:DisassociateService",
L59:             "aidevops:ListWebhooks"
L60:           ],
L61:           "Resource": "arn:aws:aidevops:us-east-1:111122223333:agentspace/*",
L62:           "Condition": {
L63:             "StringEquals": {
L64:               "aws:ResourceTag/team": "platform"
L65:             }
L66:           }
L67:         }
L68:       ]
L69:     }`
L70: ## Investigation and execution actions
L71: 
L72: These actions control access to incident investigation features:
L73: 
L74:   * aidevops:ListExecutions – Allows you to view execution metadata, including ID, status, and more, for investigations, mitigations, evaluations, and chat conversations associated with a task.
L75:   * aidevops:ListJournalRecords – Allows users to access detailed logs that show the agent's reasoning steps, actions taken, and data sources consulted during an investigation, mitigation, evaluation, and chat conversation. This is useful for understanding how the agent reached its conclusions.
L76: ## Chat management actions
L77: 
L78: Chat requires the following IAM permissions to function:
L79: 
L80:   * aidevops:ListChats – Allows users to list and access chat conversation history.
L81: 
L82:   * aidevops:CreateChat – Allows users to create new chat conversations.
L83: 
L84:   * aidevops:SendMessage – Allows users to submit queries and receive streaming responses.
L85: 
L86:   * aidevops:GetChat – Allows users to retrieve a chat conversation and its metadata, including the current title and archive status.
L87:   * aidevops:UpdateChat – Allows users to rename or archive a chat conversation. This permission is required for both rename and archive actions in the web app.
L88: ## Topology and discovery actions
L89: 
L90: These actions control access to application resource mapping features:
L91: 
L92:   * aidevops:DiscoverTopology – Allows users to trigger topology discovery and mapping for an Agent Space. This action initiates the process of scanning AWS accounts and building the application resource topology.
L93: ## Prevention and recommendation actions
L94: 
L95: These actions control access to the Prevention feature:
L96: 
L97:   * aidevops:ListGoals – Allows users to view prevention goals and objectives that the agent is working toward based on recent incident patterns.
L98: 
L99:   * aidevops:ListRecommendations – Allows users to view all recommendations generated by the Prevention feature, including their priority and category.
L100:   * aidevops:GetRecommendation – Allows users to view detailed information about a specific recommendation, including the incidents it would have prevented and implementation guidance.
L101: ## Backlog task management actions
L102: 
L103: These actions control the ability to manage recommendations as backlog tasks:
L104: 
L105:   * aidevops:CreateBacklogTask – Allows users to create an incident investigation or prevention evaluation task. Users also need this permission to run a custom agent on demand.
L106: 
L107:   * aidevops:UpdateBacklogTask – Allows users to approve a mitigation plan or cancel an active investigation or evaluation.
L108: 
L109:   * aidevops:GetBacklogTask – Allows users to retrieve details about a specific task.
L110:   * aidevops:ListBacklogTasks – Allows users to list tasks for an Agent Space, filtered by task type, status, priority, or creation time.
L111: ## Asset management actions
L112: 
L113: These actions control the ability to add and manage assets in an Agent Space, including skills, AGENTS.md files, attachments, custom agents, test profiles, and feedback. For details on the Asset API, see 【18†Managing assets】.
L114: 
L115:   * aidevops:CreateAsset – Allows users to create a new asset in an Agent Space, including skills, AGENTS.md files, attachments, custom agents, test profiles, and feedback.
L116:   * aidevops:GetAsset – Allows users to retrieve an asset's metadata and version information.
L117: 
L118:   * aidevops:UpdateAsset – Allows users to update the metadata or content of an existing asset.
L119: 
L120:   * aidevops:DeleteAsset – Allows users to delete an asset and all of its files from an Agent Space.
L121: 
L122:   * aidevops:ListAssets – Allows users to list assets in an Agent Space, with optional filtering by asset type.
L123: 
L124:   * aidevops:ListAssetVersions – Allows users to list the historical versions of an asset.
L125:   * aidevops:GetAssetContent – Allows users to download an asset's full content as a zip bundle.
L126: 
L127:   * aidevops:CreateAssetFile – Allows users to add a new file to an existing asset.
L128: 
L129:   * aidevops:GetAssetFile – Allows users to retrieve a single file from an asset by its path.
L130: 
L131:   * aidevops:UpdateAssetFile – Allows users to replace the content or metadata of an existing file in an asset.
L132: 
L133:   * aidevops:DeleteAssetFile – Allows users to remove a single file from an asset.
L134:   * aidevops:ListAssetFiles – Allows users to list the files within an asset.
L135: 
L136:   * aidevops:ListAssetTypes – Allows users to list the asset types supported by AWS DevOps Agent. This action is not scoped to a specific Agent Space and requires `Resource: "*"`.
L137: ## Catalog actions
L138: These actions control access to the AWS DevOps Agent Skills Catalog. In these action names, a capability is an item in the catalog, such as a skill. The Skills Catalog uses `aidevops:ListCatalogCapabilities`, `aidevops:GetCatalogCapability`, and `aidevops:ListCatalogCapabilityFiles`, but not `aidevops:ListCatalogCapabilityTypes`. The actions aren't scoped to a specific Agent Space and require `Resource: "*"`.
L139: To add skills from the Skills Catalog to an Agent Space, you also need `aidevops:CreateAsset`, and to sync them, `aidevops:UpdateAsset`. For more information, see 【19†Skills Catalog】.
L140:   * aidevops:GetCatalogCapability – Allows users to retrieve a capability and its files from the catalog.
L141: 
L142:   * aidevops:ListCatalogCapabilities – Allows users to list the capabilities in the catalog.
L143: 
L144:   * aidevops:ListCatalogCapabilityFiles – Allows users to list the files in a capability from the catalog.
L145: 
L146:   * aidevops:ListCatalogCapabilityTypes – Allows users to list the capability types in the catalog.
L147: ## Trigger management actions
L148: 
L149: These actions control the ability to manage triggers that run custom agents automatically, on a schedule or when an event arrives. For details on triggers, see 【20†Executing custom agents】.
L150: 
L151:   * aidevops:CreateTrigger – Allows users to create a trigger for a custom agent in an Agent Space.
L152: 
L153:   * aidevops:GetTrigger – Allows users to retrieve the details of a specific trigger.
L154: 
L155:   * aidevops:UpdateTrigger – Allows users to update the configuration of an existing trigger.
L156:   * aidevops:DeleteTrigger – Allows users to delete a trigger from an Agent Space.
L157: 
L158:   * aidevops:ListTriggers – Allows users to list the triggers in an Agent Space.
L159: ## AWS Support integration actions
L160: 
L161: These actions control integration with AWS Support cases:
L162: 
L163:   * aidevops:InitiateChatForCase – Allows users to start a chat session with AWS Support directly from an investigation, automatically providing context about the incident.
L164: 
L165:   * aidevops:EndChatForCase – Allows users to end an active AWS Support case chat session.
L166: 
L167:   * aidevops:DescribeSupportLevel – Allows users to check the AWS Support plan level for the account to determine available support options.
L168: ## Access token management actions
L169: 
L170: These actions control access to access token operations for remote MCP and A2A server authentication:
L171: 
L172:   * aidevops:CreateAccessToken – Allows users to create access tokens for an Agent Space.
L173: 
L174:   * aidevops:GetAccessToken – Allows users to view access token details.
L175: 
L176:   * aidevops:ListAccessTokens – Allows users to list access tokens in an Agent Space.
L177:   * aidevops:RotateAccessToken – Allows users to rotate an access token, generating a new value while preserving configuration.
L178: 
L179:   * aidevops:RevokeAccessToken – Allows users to revoke an access token, permanently disabling it.
L180: ## Usage and monitoring actions
L181: 
L182: These actions control access to usage information:
L183: 
L184:   * aidevops:GetAccountUsage – Allows users to view the AWS DevOps Agent monthly quota for investigation hours, prevention evaluation hours, and chat requests, as well as the current month's usage.

L294: ## Using service-linked roles for AWS DevOps Agent
L295: 
L296: AWS DevOps Agent uses AWS Identity and Access Management (IAM) 【21†service-linked roles】. A service-linked role is a unique type of IAM role that is linked directly to AWS DevOps Agent. Service-linked roles are predefined by AWS DevOps Agent and include all the permissions that the service requires to call other AWS services on your behalf.
L297: ### Service-linked role permissions
L298: 
L299: The `AWSServiceRoleForAIDevOps` service-linked role trusts the `aidevops.amazonaws.com` service principal to assume the role.
L300: 
L301: The role uses the managed policy `AWSServiceRoleForAIDevOpsPolicy` with the following permissions:
L302: 
L303:   * `cloudwatch:PutMetricData` – Publish usage metrics to the `AWS/AIDevOps` CloudWatch namespace. Scoped by a `cloudwatch:namespace` condition to only allow the `AWS/AIDevOps` namespace.
L304:   * `cloudwatch:GetMetricData` – Read usage metrics from the `AWS/AIDevOps` CloudWatch namespace. This read-only action applies to all resources because the CloudWatch API does not support resource-level permissions or the `cloudwatch:namespace` condition for `GetMetricData`.
L305:   * `vpc-lattice:CreateResourceGateway` – Create VPC Lattice resource gateways for private connections. Scoped by an `aws:RequestTag/AWSAIDevOpsManaged` condition so the service can only create resource gateways that carry the `AWSAIDevOpsManaged` tag.
L306: 
L307:   * `vpc-lattice:TagResource` – Tag VPC Lattice resource gateways. Scoped by an `aws:RequestTag/AWSAIDevOpsManaged` condition.
L308:   * `vpc-lattice:DeleteResourceGateway` – Delete VPC Lattice resource gateways. Scoped by an `aws:ResourceTag/AWSAIDevOpsManaged` condition so the service can only delete resource gateways it created.
L309: 
L310:   * `vpc-lattice:GetResourceGateway` – Retrieve information about VPC Lattice resource gateways. Scoped by an `aws:ResourceTag/AWSAIDevOpsManaged` condition so the service can only read resource gateways it created.
L311:   * `ec2:DescribeVpcs`, `ec2:DescribeSubnets`, `ec2:DescribeSecurityGroups` – Retrieve information about VPC networking resources required to configure resource gateways. These read-only actions apply to all VPC resources because the EC2 API does not support resource-level permissions for Describe calls.
L312:   * `iam:CreateServiceLinkedRole` – Create the VPC Lattice service-linked role required for resource gateway operations. This permission is scoped to the `vpc-lattice.amazonaws.com` service principal only and cannot be used to create service-linked roles for any other service.
L313: ### Creating the service-linked role
L314: 
L315: You don't need to manually create the `AWSServiceRoleForAIDevOps` service-linked role. When you start using AWS DevOps Agent, the service creates the service-linked role for you.
L316: To allow the service to create the role on your behalf, you must have the `iam:CreateServiceLinkedRole` permission. We recommend scoping this permission with an `iam:AWSServiceName` condition for `aidevops.amazonaws.com` to follow the principle of least privilege. For more information, see 【22†Service-linked role permissions】.
L317: ### Editing the service-linked role
L318: 
L319: You cannot edit the `AWSServiceRoleForAIDevOps` service-linked role. After the role is created, you cannot change the name of the role because various entities might reference the role by name. However, you can edit the description of the role using IAM. For more information, see 【23†Editing a service-linked role】.
L320: ### Deleting the service-linked role
L321: If you no longer need to use AWS DevOps Agent, we recommend that you delete the `AWSServiceRoleForAIDevOps` service-linked role. Before you can delete the role, you must first remove any private connections configured in your Agent Space. Deleting the service-linked role does not automatically remove VPC Lattice resource gateways tagged with `AWSAIDevOpsManaged` that were previously created by the service. You should delete these resource gateways manually if they are no longer needed.
L322: For more information, see 【24†Deleting a service-linked role】.
