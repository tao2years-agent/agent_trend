## 五个可以单独验证的产品机会

|可试做的能力|用户面临的具体决定|已有技术与剩余缺口|最快的否证办法|
|---|---|---|---|
|审查容量限制派工|维护者周一面对几十个跨仓升级，先处理哪几个？|Symphony 能按工单和可用槽位调度，Graphite 能处理相互依赖的合并队列。可试的增量是让派发同时受有权评审者时段、每服务在途上限和待发布存量限制。[F01] [M06] [P11]|相同团队按周交替采用固定并发和容量约束；若队列缩短但发布验收总数也下降，查真实瓶颈并撤销上限。|
|把“接管”记录成下次可回放的测试|操作人纠正了哪个错误前提，改 recipe 后还会再犯吗？|Tessl 比较同任务有/无 skill，还能观察 skill 是否加载；Phoenix 绑定数据集版本。可加一项业务规则：把有效纠正连到独立验收，维持全程未参与调优的失败集。[F03] [O05] [I16]|对有证据能重放的纠正做配对实验；若载入了 skill 但盲审结果不变，停止推广它。|
|为审批写明对象和有效期|原计划刚获批、新提交改变目标对象，平台应否继续？|Atlantis 将计划完整性与部分执行条件分开验证；Jenkins Input Step 限制谁能提交决定。跨系统时需要把人、对象、内容摘要、时间、作用域放到同一条决策记录。[D08] [D11] [O08]|在沙箱批准 A 后替换成 B 或撤回权限；观察旧授权能否放行，以及正确授权多久能恢复工作。|
|无人持有的自动化转交与退役|创建者调岗后，定时任务用谁的连接器？过去一个月有几次输出被真正使用？|Claude Code Scheduled tasks 由个人拥有，Devin Bots 的 Bot 可拥有自己的权限。相同“无人值守”有不同的身份生命周期。可试做 owner 交接、过期暂停、无人消费退役。[F04] [M02] [I06]|在隔离环境做转岗模拟，跟踪旧连接器最后一次有效使用；低频灾备流程单列，不能因平时少用就删除。|
|按结果计费和选择执行环境|一次耗时回放沉默了，应继续付费还是先休眠？|OpenSandbox 区分没有活动证据与真正空闲，OpenCost 能拆 Kubernetes 资源成本，DevLake 能关联部分交付事件。仍需补 SaaS 调用、没有结果的尝试和人的维护时间。[F05] [O11] [O02]|对相同任务比较保温、休眠和即时创建，记录复苏延迟、重复动作、每次被接纳结果的完整成本；便宜但恢复慢到阻塞人时应收缩。|

共性是把“组织的规则有没有真的改变动作”做成可观察的事实。可由日程、事件和 webhook 触发的工作近乎无限，而愿意维护的规则、能给出验收的人和稳定的生产信号都很有限。选题时优先找已经出现真实排队和重复判断的环节，这比先定义统一的自治等级更容易获得可反驳的结果。

## 同一工单的可实施设计

|事件及输入|持久化对象|状态与人能做的动作|
|---|---|---|
|工单重复到达、任务被拆分|来源系统 + 工单号 + 输入修订；父子任务；owner；策略修订|更高修订让旧批准过期，重复事件合并。暂未分配 owner 的任务只读排查。[F01] [O01]|
|接到执行并占用资源|attempt ID、隔离工作区、机器身份、租约与并发上限|有期限的执行权；lease 到期后核验外部动作再重领。重复发起可识别。[F01] [E11]|
|验证结论产生|输入修订、验证器版本、环境标识、样本数、预期与实测值、结果链接|成功、失败、无结论、没有数据独立建模。保留首个失败和最终一次测量。[D05] [O10]|
|例外出现或超时|待决问题、仍未知事项、可逆/不可逆影响、审批内容摘要和授权主体|可拒绝、延后、暂停新动作、取消在途请求或交接。每个动作记录系统确认时间。[D02] [D03] [D08]|
|修复上线与复核|部署版本、生产观察窗、对照群体、复发与最终 disposition|由发布平台、服务 owner 确认结果。验收失败重开原工单；对已到期日志保留证据失效状态。[I16] [I24]|
|维护规则和退出|失败标签、旧新策略、训练/留出数据集、观察窗、适用服务与生效版本|先只读影子运行，再有限推广，可暂停和退回旧版本。商业托管退出时导出工件并实测能否重建。[F03] [O05] [M03]|

这是建议的数据边界，可分批实现。首版可用已有 CI 工单、自定义字段、对象存储及 PR 检查。只在拿到试点增量之后才值得做跨产品的统一控制台。
