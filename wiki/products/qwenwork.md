# 千问办公 2.0

## 判断

千问办公 2.0 是核心样本中最明确以“Team Agent”重构办公协作对象的产品之一。它没有只做一个可分享 Prompt，而是将协作空间、数字员工、空间记忆、待办、定时任务、资料空间和人机共创串成工作闭环。[官方事实]

其产品核心不是“更多生成格式”，而是让信息、行动和成果在团队内连续流转：群聊/听记/文档成为共同上下文，数字员工在空间内接单，待办和定时任务维持推进，成果进入资料空间并继续编辑。[研究推断]

## 关键机制

- 协作空间按企业组织使用；创建者从当前企业选择协作者。
- 数字员工可配置名称、头像、技能与回复规则，单独消耗/限制积分。
- 群聊等数据源的关联受原系统权限与审批影响；提交申请不等于已经取得读取授权。
- 空间记忆可查看、纠正和停用，降低“黑箱长期记忆”风险。
- 自动任务可按消息/事件/计划启动；纯云端任务在电脑关闭后仍可运行。
- 个人与企业账号数据隔离；企业侧提供成员、权限、用量、连接器和审计控制。

## 值得借鉴的产品取舍

1. Agent 不是悬浮入口，而是空间成员；协作发生在任务和资料所在处。
2. 记忆必须可见、可纠正、可停用，否则团队共识会被错误记忆悄悄污染。
3. 自动化结果需要展示未执行/失败原因，主动性不能牺牲可解释性。
4. “资料空间 + 共创编辑”使 Agent 交付物脱离会话，成为组织资产。

## 限制与未验证

当前公开文档显示空间绑定单一企业组织，未证明跨企业成员、外部 Agent 或联邦身份可以进入同一空间。管理员角色文档还提示后台权限按页面授权，不能在同一页面细分只读/编辑；开放平台 API 权限又是另一套控制。这说明“后台 RBAC”和“运行时 Agent 权限”不能当成同一层。[官方事实 + 研究推断]
