# Repo Wiki

Generate structured repository documentation and keep project knowledge up to date as code changes.

Repo Wiki analyzes your project structure and implementation to generate structured documentation covering architecture, module relationships, and business workflows. It tracks code changes so Qoder can combine project knowledge with task context to understand the codebase, locate implementations, and assess change impact. Repo Wiki and Knowledge Cards provide project knowledge that agents can use as context during development tasks.

Use cases

  * Understand architecture and implementation: Explore module responsibilities, service dependencies, and call chains. For example, ask which modules handle order creation.
  * Develop and troubleshoot: Review related implementations and constraints before adding features, fixing issues, or refactoring to narrow your code search.
  * Learn a project: Use the documentation tree to explore the overall structure, core workflows, and design decisions, helping new contributors get started.

##

Find a repository

  1. Open More in the sidebar and select Repo Wiki, or use its current location if you customized the sidebar.
  2. Search for the repository, then use Generation Status to show All, Generated, or Not generated projects.
  3. Switch between Grid view and List view when that makes the list easier to scan. Select Refresh to reload status.
If the entry is missing or you want it directly in the sidebar, see Customize sidebar navigation.

Generate Repo Wiki

  1. Open a repository that is marked Not generated, or select Go to generate.
  2. Choose English or 简体中文 under Language.
  3. Review the generation options:
     * Auto Update incrementally refreshes the Wiki when code changes.
     * Auto Export exports knowledge to the project's `.qoder/repowiki` directory after generation or updates.
     * Citation lets agents use the generated knowledge as task context.
  4. Select Generate.
Generation runs against the current codebase. Before starting, switch to the target branch and prepare the code and project documentation you want the Wiki to reference. The initial generation creates both Wiki pages and Knowledge Cards. After generation, search for or select a Wiki page on the left to read it on the right. Select Repo Wiki Overview to check the generation status, document count, and update time. Switch to the Knowledge cards view to explore the extracted project knowledge.

Updates and maintenance

  * Incremental updates: After committing code changes, select Update to refresh affected knowledge. Enable Auto Update to run incremental updates automatically. This feature compares commits and is available only for Git repositories.
  * Pause and resume: Pause generation or updates, then resume from the saved progress. Follow the page instructions to retry recoverable failures.
  * Regenerate: Select Regenerate to replan the documentation structure or rebuild it from scratch, replacing existing generated content with the current configuration.
Auto Update and Auto Export are off by default. Change them in the generation settings or the More (…) menu.

Use it in a task

With Citation enabled, open a task in the same workspace. Qoder uses project knowledge as needed. You can also state the question or intended change explicitly, for example:

  * Explain how a request moves through the main modules.
  * Locate the implementation and callers of a feature.
  * Summarize dependencies and likely impact before a change.
  * Identify repository conventions that should guide an implementation.
Repo Wiki provides project context, but runtime behavior can still differ from documentation. Confirm critical conclusions against current code, configuration, tests, and runtime output.
You can make targeted edits, add sections, or rewrite pages, using design documents or API documentation as reference. For example: "Add the order cancellation conditions to the order workflow and update the related API descriptions." Review the changes in Repo Wiki, then export if you need files. Wiki pages and Knowledge Cards are maintained separately; specify both when you want to update both. Later code updates may regenerate affected pages, so review important revisions afterward.

Repo Wiki Sharing

  * Share through Git: After exporting, commit and push `.qoder/repowiki` to a remote branch. Team members can pull the files with `git pull`, then import them to reuse the knowledge.
  * Pull from team: Accounts with team knowledge sharing can select Pull from team in the More (…) menu to retrieve published team knowledge for the same remote repository, current branch, and language.

Pulling from the team replaces local Wiki pages and Knowledge Cards for the current branch and language with the team version. Check any local revisions you want to keep before proceeding.

When account and organization policy allow, Qoder can automatically retrieve available team knowledge for the current repository, branch, and language. You can still use the existing team-pull action to retrieve it manually.

Multilingual Support

Repo Wiki supports English and Simplified Chinese. Choose a language when generating. Knowledge is stored separately for each language and exported to `.qoder/repowiki/en/` or `.qoder/repowiki/zh/`. Switch languages to view or generate the corresponding content.

Import and export

On the repository's Repo Wiki detail page, open More (…) to import or export project knowledge for the current branch and language:

  * Export to `.qoder/repowiki`: Save existing Wiki pages and Knowledge Cards to the project directory for backup and Git sharing. Wiki content is saved as Markdown; Knowledge Cards are stored under `knowledge/<language>/`. Enable Auto Export to export automatically after generation or updates.
  * Import from `.qoder/repowiki`: Read existing Wiki pages and Knowledge Cards from the project directory and replace the corresponding current content after confirmation. Use this after pulling files through Git or editing them manually, without regenerating.

Image: Qoder App Repo Wiki import and export

Keep the complete `.qoder/repowiki` directory structure when sharing or moving it, including the Wiki's `content/` and `meta/repowiki-metadata.json`. Export overwrites the corresponding language directories, so import any manual file edits before exporting.

# Repo Wiki

Repo Wiki automatically generates structured documentation for your project and continuously tracks changes in code and documentation. When you query knowledge points, code explanations, or add feature enhancements during development, Repo Wiki deeply analyzes the project structure and code implementation. Combining Repo Wiki with context information, it provides more accurate and detailed answers and documentation support, giving the agent a deeper understanding of the codebase.

Use Cases

  * Architecture and Implementation Queries
Relying on pre-built architectural knowledge, the agent can quickly answer questions like "How is X implemented?" or "Which services depend on this module?" with almost no need to invoke tools.
  * Agent-Driven Development Tasks
When context width is limited, Repo Wiki accelerates code location, supporting tasks such as:
    * Adding new features
    * Fixing bugs

Repo Wiki Generation

The Wiki in your repository is not static—it stays synchronized with your code. The Wiki updates in three key scenarios. Understanding when and why it triggers helps you keep the Wiki updated in real-time.

  1. Initial Wiki Generation When you open a project for the first time, no Wiki exists by default. You can generate it from scratch with one click.
  2. Code Changes Detected After the initial generation, the system continuously monitors code changes. If you modify content already recorded by the Wiki (e.g., function signatures, class definitions, API endpoints), the system detects the inconsistency between the current code and the existing Wiki. You can click Update to regenerate only the affected parts.
  3. Git Directory Sync If you directly edit Markdown files in the Git directory, the system detects inconsistencies between the Git content and the Wiki. You can click Sync to synchronize the Git changes and update the Wiki.
  4. Generation Limits
     * A maximum of 10,000 files per project. If your project contains more than 10,000 files, it is recommended to exclude non-essential paths in Qoder IDE Settings → Codebase Indexing → Index Exclusions.
     * Only supports Git repositories with at least one commit.

Intervening in Wiki Generation

Repo Wiki is not a "generate once and read-only" artifact. You can guide the direction through a configuration file before generation, or modify it anytime after generation. Every knowledge revision made by the team is recognized by the system as new cognitive deposits—it won't be overwritten by the next automatic update, but instead reverse-synced to the corresponding knowledge cards—truly embedding human judgment into knowledge assets.

/knowledge Command

Type `/knowledge` in the chat input to intervene in Repo Wiki and Knowledge Cards:

Operation  | Description
--- | ---
Generate  | Generate Wiki or Knowledge Cards for the project for the first time
Modify  | Make partial modifications to existing knowledge content
Supplement  | Append new content to existing knowledge
Rewrite  | Completely rewrite a knowledge page or card

How to use:

  1. Invoke `/knowledge` in the input box
  2. Enter your instruction describing the desired changes
  3. Optionally upload local files as reference (e.g., design docs, API docs)
  4. The Agent will modify the corresponding knowledge content based on your instruction
Manually modified content is marked and protected by the system—it won't be overwritten during the next automatic update, making every team knowledge revision a persistent knowledge asset.

Repo Wiki Sharing

Supports Wiki sharing to facilitate more efficient knowledge flow within the team. Once a team administrator enables the Knowledge toggle in the Web console, any Repo Wiki generated by a team member is automatically synced to the team. Other members simply open the same repository branch and click Generate to automatically retrieve the team's latest knowledge—no manual pulling required. Any changes to the project's knowledge by team members are synced to everyone, ensuring the team's knowledge stays consistent and up-to-date.

Automatic team sharing is only available in the Teams plan. Alternatively, you can manage knowledge via Git sync.

Team sharing syncs the generated Wiki documentation content only; it does not involve uploading the source code itself.

When generating a Wiki locally, the system automatically creates a dedicated directory in your code repository: `.qoder/repowiki`.

Image: Wiki Sharing

You can commit and push this directory to a remote branch. Team members can then pull the generated Wiki content via `git pull`—no extra configuration required.

Multilingual Support

The Wiki system supports multiple languages—you can select your preferred language when generating the Wiki. Currently, English and Chinese are supported. When generating the Wiki, the system automatically creates independent directories for each selected language under the Git directory based on your language choices (e.g., `repowiki/zh/`, `repowiki/en/`).

Data Security

Repo Wiki generation runs on your local client: it launches multiple Agents locally to handle task planning, code retrieval, documentation structure planning, and similar work. Agents only read the files in your repository that the task requires.

  * No full-codebase upload: your complete codebase is never uploaded to the cloud during generation.
  * No server-side retention: your code is not stored on the server; generated results are saved only in your local repository.
  * Off by default: Repo Wiki is off by default and must be enabled by you; automatic incremental updates can be turned on or off at your discretion.--------------------------------------------------------------------------------

# Knowledge Card

Generated synchronously with the Repo Wiki, a Knowledge Card is a high-density knowledge unit extracted from code. It stores architecture documents, code specifications (Spec), and tech stack information in a format that the Agent can easily consume directly. It continuously tracks code changes during every commit, maintaining real-time accuracy and relevance.

Use Cases

  * Architecture Document-Driven System Understanding: Based on pre-built architecture documents, the Agent can quickly answer questions like "What is the overall design concept of this module?" or "What are the dependencies between these services?" without repeatedly searching the codebase.
  * Code Specification (Spec)-Guided Development Tasks: When you need to ensure code style, interface design, or business logic complies with team standards, the Agent can refer directly to the specification knowledge, supporting scenarios like:
    * Automatically aligning with naming conventions and interface agreements when adding features

# Memory

Let Qoder reuse stable preferences and project context in later tasks.

Copy page

Memory retains information that remains useful across tasks, such as communication preferences, project background, and recurring collaboration conventions. Open Settings → Memory to view and manage long-term memory stored by Qoder on this device.

What belongs in memory

  * Stable development or communication preferences.
  * Long-lived project background and conventions.
  * Tools, validation methods, or reference locations used across tasks.
Open Settings → Memory to view and manage memory:

  * Global memory: Read and update your personal preferences, habits, and long-term context across all projects.
  * Project memory: Read and update repository rules, experience, and long-term context for each project.
You can turn each type on or off independently. The page shows the number of files in each memory directory and the latest update time. Open the corresponding directory to inspect its contents, or clear that type of memory. Address outdated, inaccurate, or no-longer-needed information promptly. Do not store passwords, verification codes, API keys, or temporary task state.

# Knowledge Cards

Capture project architecture, coding conventions, and tech stack details for Qoder to use in tasks.

Knowledge Cards are compact knowledge units extracted from your codebase. Together with Repo Wiki, they provide project context for Qoder. Cards record architecture, coding conventions, and tech stack details to help agents understand projects, write code, and troubleshoot issues.

Knowledge Card Types

  * Architecture Documents: Record module structure, service dependencies, and design decisions to explain system architecture and change impact.
  * Code Specifications (Spec): Capture naming conventions, interface agreements, and business constraints for development, code review, and troubleshooting.
  * Tech Stack: Record the frameworks, libraries, and versions used in the project to guide dependency choices and implementation.

Generate and view Knowledge Cards

  1. Open More in the sidebar, select Repo Wiki, and open the target repository.
  2. Switch to the Knowledge cards view and choose English or 简体中文 under Language.
