# Agentic memory for GitHub Copilot is in public preview

Copilot memory is now available in public preview for all paid GitHub Copilot plans.

Copilot memory enables Copilot to learn and retain useful details about your repositories. As you work with Copilot coding agent, Copilot code review, or Copilot CLI, it builds a repository-specific understanding that improves the quality of its assistance over time.

### How it works

Copilot automatically captures tightly scoped insights called “memories” as it works in your repositories. These memories are:

  * Repository-specific and validated against the current codebase before use.
  * Shared across Copilot features, so what coding agent learns can help code review.
  * Automatically expired after 28 days to prevent stale information.

For more details on how exactly Copilot memory works, check out our engineering blog post on Copilot memory.

### Get started

  * Individual users (Copilot Pro or Pro+): Enable Copilot memory in your personal Copilot settings.
  * Organizations and enterprises: Enable through policy settings in your organization or enterprise settings.

Repository owners can review and delete stored memories in Repository Settings > Copilot > Memory.

To learn more about how to use this feature, check out our Copilot memory documentation.--------------------------------------------------------------------------------

# Copilot Memory now on by default for Pro and Pro+ users in public preview

Copilot Memory is now enabled by default for all GitHub Copilot Pro and Copilot Pro+ users.

Previously in public preview as an opt-in feature, Copilot Memory allows Copilot to build and retain a persistent, repository-level understanding of your codebase so you spend less time reexplaining context and more time shipping code.

## What is Copilot Memory?

Copilot Memory enables Copilot agents to discover and store useful facts about a repository (e.g., coding conventions, architectural patterns, and critical cross-file dependencies) and reuse that knowledge in future interactions. Memories are strictly scoped to a single repository and validated against the current codebase before being applied, so stale or inaccurate context is never used. To keep things fresh, memories automatically expire after 28 days.

Once enabled, Copilot Memory works across:

  * Copilot coding agent: Applies repository-specific context when implementing tasks and opening pull requests.
  * Copilot code review: Uses learned patterns to give more accurate, targeted review feedback.
  * Copilot CLI: Brings repository awareness directly to your terminal workflow.

Because memories are shared across agents, knowledge discovered by the coding agent can immediately benefit code review and vice versa.

## What’s changing

Copilot Memory is now on by default for individual users on Copilot Pro and Copilot Pro+ plans. No action is required to start benefiting from it.

If you prefer to opt out, you can disable Copilot Memory at any time in your personal Copilot settings under Features > Copilot Memory.

Enterprise and organization admins retain full control over memory availability for their members via Copilot policies at the enterprise and organization levels.

## Managing memories

Repository owners can review and delete stored memories at any time under Repository Settings > Copilot > Memory.

For more information, see About agentic memory for GitHub Copilot and Enabling and curating Copilot Memory.

# Copilot Memory has more controls for deletion, scope, and the Copilot CLI

Copilot Memory now includes improved memory deletion, adds a repository-level off switch, and brings further memory controls into the Copilot CLI. Copilot Memory is in public preview and available to all paid Copilot plans.

## What’s changing

  * Deletion guidance: When you ask Copilot to forget something, it now points you to the right place to remove the memory and down-votes the memory where voting is available.
  * Repository-level off switch: Repository admins can now disable Copilot Memory for a repository from the existing Copilot feature controls in repository settings. Repository-level facts will no longer be stored or read. Preexisting facts are not deleted. User-level preferences are unaffected.
  * `/memory` command in the Copilot CLI: Use `/memory on` to enable Copilot Memory, `/memory off` to disable it, and `/memory show` to check its current status. Your choice persists across sessions.
  * Clearer scope at capture time: The `store_memory` permission prompt now explicitly states whether the entry will be a user-level preference (i.e., visible only to you, used in your sessions across repositories) or a repository-level fact (i.e., visible to all contributors on the repository).

## Managing memories

  * Your user-level preferences: Review or delete them in your personal Copilot Memory settings.
  * Your repository’s facts: Repository owners can review, delete, or turn off Copilot Memory for the repository under Repository Settings > Copilot > Memory.

Learn more about managing stored memories.

# GitHub intelligence puts your code, context, and history to work

Agents should understand more than your codebase—they should understand how your team works. Your preferences, repository conventions, skills, and custom instructions guide how changes should be made, while code in related repositories can show how the pieces fit together. Without that context, agents spend time rediscovering knowledge and can miss your team’s conventions.

GitHub intelligence is the context and learning layer sourced from the graph of GitHub data. It makes this data useful to agents, helping them remember how you work, keep that guidance current, and find the code and development history relevant to the next task. The goal is for agents to build on what you and your team already know, rather than treating every session as a fresh start.

That is the advantage of building where your team’s work already lives. A repository memory can capture why an edge case matters and which test covers it. GitHub intelligence allows agents to use that context, with controls over what they can access.

Three capabilities bring this into your workflow:

  * Memory carries knowledge between sessions
  * Dreaming keeps the context current
  * Code search reaches beyond your checkout.

Availability and settings vary by capability.

### Memory: Pick up where you left off

GitHub Copilot Memory is now generally available on paid Copilot plans. Copilot can remember personal preferences and repository conventions across sessions and clients. Memories can be created in the Copilot app, Copilot CLI, VS Code, Copilot cloud agent, Copilot code review, Slack, Teams, and GitHub Mobile.

You can tell Copilot, `Remember to start my pull request descriptions with a TL;DR`, and it can reuse that preference across Copilot experiences. Repository memories can capture the right test command or how your team expects Copilot to check its work, so you spend less time repeating guidance in each session. Copilot sessions autonomously generate and curate memories, learning from every interaction.

Among the Copilot CLI sessions reviewed during the public preview where the agent used memory, 93% showed better adherence to developer preferences and 42% showed more efficient workflows attributed to the memories included in the session context.

You can interact with memories in the Copilot app, Copilot CLI, and VS Code, or manage personal memories in your Copilot settings, where you can view or delete saved preferences.

### Dreaming: Continuous context improvement

Copilot dreaming, now in public preview, reflects on past work to improve future agentic sessions.

Three dream types are currently available:

  * Personal memory curation customizes Copilot to your personal preferences by updating memories based on your agent conversations.
  * Repository customization manages repository-scoped memories and proposes updates and improvements to existing skills and custom instruction files.
  * Code review customization turns recurring accepted code-review feedback into guidance for Copilot code review.

Dreaming can add, update, and remove personal and repository memories. Changes to checked-in skills and instructions are proposed in pull requests for your team to review.

Dreaming is opt-in.

  * Individual subscribers: Enable personal curation in your Copilot settings and repository dreams in each repository’s settings. See personal and repository setup.
  * Organizations and enterprises: Administrators enable dreaming through Copilot policies. Enterprise administrators can delegate that choice to organization administrators. Repository dreams cover the repositories allowed by Copilot Memory’s repository access settings. Users must also enable personal dreaming in their own Copilot settings.

Dream runs consume AI credits. See the dreaming documentation for prerequisites, setup, and costs.

### Code Search: Reach beyond your checkout

Software projects rarely live in a single repository. GitHub code search helps Copilot find relevant code, configuration, schemas, and documentation across related projects and dependencies without needing a local clone. Copilot can search for exact text and symbols, match patterns with regular expressions, and narrow results by repository, path, or language. Semantic search can also find code by what it does, such as retrying a failed payment, even when you don’t know the file, function name, or repository it lives in.

For example, you’re fixing failed payments, but retry behavior spans a payments service, a shared library, and background workers. Use `/research` to ask Copilot, `How do these components retry failed charges, and where could retries overlap?` Copilot can inspect implementations and callers across those repositories to help you understand how the system fits together before changing it.

That unlocks workflows that would otherwise require you to assemble the context yourself:

  * Plan a migration: Use `/research` to identify implementations and callers across repositories, plan the changes each service needs, and check which projects still use the old API.
  * Investigate a bug: Trace related implementations across services and shared libraries, bring specific code references into the investigation, and use that context to propose a coordinated fix.
  * Follow organizational standards: Find existing patterns across your organization and use them to guide changes in an unfamiliar codebase.

Whether the task calls for an exact symbol, a regular expression in file contents or paths, or a natural-language description, Copilot can search across repositories in your organization to find relevant context. You spend less time cloning projects, tracking down files, and copying code into the conversation. In addition, Copilot gets the context it needs to make the right changes.

### Try it today

Your team shouldn’t have to teach every agent the same lessons. GitHub intelligence helps agents carry those lessons forward, find the context they need, and put more of each session toward the work you actually want done.

# Copilot code review and coding agent now support agent-specific instructions

You can now craft targeted custom instructions for Copilot code review and Copilot coding agent. The new `excludeAgent` property for `.instructions.md` custom instructions gives you exact control over when specific instructions apply.

### 🎯 Recap: Customizing Copilot using `instructions.md` files

You can already use custom instruction files located in your `.github/instructions` directory to guide Copilot’s behavior for specific areas of your repository.

The `applyTo` property lets you specify paths or directories with path globs, so your instructions apply where you want them to, and nowhere else. For example, you could create a `models.instructions.md` file which only applies to your models by specifying `applyTo: "app/models/**/*.rb"`.

### 🛡️ Introducing agent-specific repository instructions with `excludeAgent`

The new `excludeAgent` property allows you to control which Copilot agents use a given instructions file:

  * Set `excludeAgent: "code-review"` to hide your instructions file from Copilot code review.
  * Set `excludeAgent: "coding-agent"` to hide your instructions file from Copilot coding agent.

If you don’t have an `excludeAgent` property in your frontmatter, your instructions file will be used by all agents.

This feature ensures you can tailor your guidance for each agent, reducing overlap and allowing you to provide focused, specific instructions.

### 🛠️ Other custom instructions improvements

Copilot code review recently fixed a bug that prevented it from reading certain `*.instructions.md` files.

For tips on how to write effective instructions files, check out this blog post!

For details on creating instructions files, visit the Copilot instructions documentation.

# GitHub Copilot coding agent now supports .instructions.md custom instructions
